# Spec addendum — Verbatim v1.3: usefulness + UI warmth

Build contract for app-developer, extending v1 / v1.1 / v1.1.1 / v1.1.2 / v1.2 / the
accuracy-mvp (all frozen or in-flight build records). Same stack and deployment — Vite +
React SPA on GitHub Pages, Supabase Postgres + pgvector + Auth + Storage + Edge Functions,
OpenRouter free model, $0 / all-OSS.

**This is a UI / product addendum, not an architecture change.** The
[product review](../docs/product-review-2026-09.md) found the *answer* is trustworthy but
everything *around* it is thin: tables flatten to prose, one frozen citation page, a spinner
that reads as broken, no starter questions, no export, no per-instrument identity. v1.3
closes those gaps for a **psychologist audience** — warm and characterful, never gimmicky.

**Nothing here touches the pipeline.** No migration, no Edge Function change — pure SPA. The
retriever (`match_chunks`), the three response kinds (`grounded` / `abstained` / `meta`), the
verify pass, and the whole eval suite are untouched; `run_evals.py --quick` stays green as a
sanity check, not a gate.

Delivery model: single generalist developer + a fresh-context `/code-review` at each phase
boundary — UI-heavy and the feel matters. Built as three phases, each with its own checkpoint
+ `/code-review`, then **one whole-addendum release-qa + ship**. Phase 1 may ship early if
tables are wanted out fast.

---

## Scope

1. **Tables in answers** — when a citation points at a chunk with `table_ref` set, the SPA
   reads that chunk's `content` (under the caller's JWT) and renders it as a real table
   below the prose answer, captioned "from the cited table, p.N".
2. **Citation viewer v2** — `SourceSlideOver` gains full-document scroll (all pages), zoom,
   prev/next, and a "search this manual" box (client-side text match over the version's
   chunk `content` — no LLM, no new retrieval). "Found it on page N" as the highlight lands;
   `Esc` closes.
3. **Staged answer progress** — replace the single "Reading the manual…" spinner with an
   honest staged status (*retrieving → drafting → checking → verified*) advanced on a client
   timer, resolving when the response lands. No pipeline change; real token streaming is a
   separate spec.
4. **Starter questions** — 3–5 authored questions per instrument (static map keyed by slug)
   on the Ask empty state, click to prefill the composer.
5. **Copy with citation** — a button on each grounded answer → plain text: the answer + each
   `Manual · p.N` + the quoted span.
6. **Manual detail page** — a new `/manual/:versionId` route (instrument, edition, publisher,
   page count, section outline, "Ask about this →"). Library rows link here instead of
   straight into Ask.
7. **UI warmth pass** (cross-cutting, folded into phases 1–3, **not** a separate "restyle"
   phase) — "calm, knowledgeable colleague" microcopy (abstain card, errors); rotating honest
   loading lines; per-instrument monogram + subtle accent tint; a citation-as-receipt
   micro-animation + a padlock "click shut" on the locked header; warm "night session"
   dark-mode polish. `prefers-reduced-motion` respected throughout.
8. **Tier-3 (in scope):** `/` focuses the composer · `Esc` closes the slide-over · a one-card
   first-run onboarding (localStorage "seen") · "N questions today" in the sidebar.

## Out of scope (each → its own spec / stays on the backlog)

Real token streaming (own spec — needs the Edge Function to stream + a "no unverified claim
shown as final" design) · cross-edition compare (own spec) · shareable answer *link* (a new
public RLS read path to `query_log` — a privacy surface; "Copy with citation" covers the
need for now) · per-answer feedback / 👍👎 (`specs/2026-09-12-verbatim-feedback.md`) · PWA ·
admin metrics tab · post-publish manual-metadata edit · audio overviews / agentic research /
workspaces / collaboration (never — they pull the tool away from "look up a fact, safely").

## Intake decisions (2026-09-12)

- **Streaming:** staged client-side progress in v1.3; real token streaming deferred.
- **Tables:** the SPA renders the cited chunk's content — **no answer-prompt change**, so no
  eval risk. (The alternative, having the answer LLM emit markdown tables, was rejected: a
  prompt change is eval-gated and the small free model mangles markdown tables.)
- **Cross-edition compare:** deferred to its own spec.
- **Tier 3:** shortcuts + onboarding + usage indicator are in; PWA + admin metrics +
  metadata-edit stay on the backlog.
- **Shareable answer link:** out — new public RLS surface, revisit separately.

## Architecture change

**None to the pipeline.** One reviewed convention exception, to record in
`.claude/rules/src.md` in Phase 1:

> The SPA may read `public.document_chunks` directly under the **caller's JWT**, for
> **source display only** — the citation viewer and the in-answer table render. It must never
> read `document_chunks` to *synthesise an answer* (that still goes only through
> `match_chunks`), and never with the service-role client. RLS
> (`document_chunks_select_via_version`) already gates this read to `active` / owned / admin
> versions — the same data a citation already exposes, just more of it.

`sourcePdfUrl(versionId)` (already student-accessible for active manuals via the
`manuals_select_active_source` storage policy) is reused by the citation viewer.

## Prior art & scope rationale

Concretely copied: **full-document citation navigation** (ChatDOC, Humata — click a citation,
land in the doc, scroll/zoom/search); **starter questions** (NotebookLM); **copy-with-citation**
(legal tools — CoCounsel, Vincent); **staged progress** (Perplexity's "searching → reading →
answering"). Deliberately cut: audio overviews, agentic multi-step research, workspaces /
real-time collaboration, web-search fallback. Full comparison + the per-persona UI reasoning
in `docs/product-review-2026-09.md`.

Verbatim's edge stays the same and must not be diluted by the warmth pass: **version
isolation, explicit abstention, the verify pass, $0 / OSS.** "Fun" for a psychologist
audience = craft and a calm colleague's voice, **not** badges, streaks, mascots, emoji-heavy
UI, jokey errors, playful display fonts, or motion that delays information.

## Phase 1 — The answer surface

**Delivers:** tables render in answers; the wait shows honest staged progress; a grounded
answer can be copied with its citations; the abstain and error states read warmly.

**Files**

- **`src/lib/api.ts`** — `citedChunkContent(chunkIds: string[]): Promise<Record<string,
  { content: string; tableRef: string | null; page: number }>>` — one
  `supabase.from('document_chunks').select('id, content, table_ref, page').in('id', ids)`
  under the caller client. Empty-array guard. Returns a map keyed by chunk id.
- **`src/components/AnswerCard.tsx`**
  - After the prose + citation row, for each **distinct cited chunk whose `tableRef` is
    non-null**, render a `<figure className="answer-table">` with the chunk `content` — as a
    real `<table>` if it parses as a pipe-delimited Markdown table, else a styled `<pre>` —
    and a `<figcaption>` "From the cited table · p.N". Fetch via `citedChunkContent` on
    mount (lazy; skip when no cited chunk has a `tableRef`).
  - A **"Copy"** action on grounded answers: `\`${answer}\n\nSources:\n${citations.map(c =>
    \`— ${manual}, p.${c.page}: "${c.quote.trim()}"\`).join('\n')}\``. `navigator.clipboard`
    with the `document.execCommand` fallback + inline "Copied" / "Press ⌘/Ctrl-C" state
    (same pattern as `History.tsx` `copyConversation`).
  - **Warm the abstain card**: heading + body to a colleague's voice, e.g. heading "Not in
    this edition", body "This version of the manual doesn't cover that. Try another edition
    from the library, or rephrase your question." Keep the amber treatment.
- **`src/routes/Ask.tsx`** — replace the `t.pending` line (`"Reading the manual…"`) with a
  `<AnswerProgress />`. Warm the failed-turn error copy (keep "Try again").
- **`src/components/AnswerProgress.tsx`** *(new)* — cycles labels on a ~2.6 s interval:
  "Finding the relevant pages…" → "Reading the manual…" → "Drafting the answer…" → "Checking
  every claim against the source…". Holds on the last label until the parent unmounts it
  (the turn resolved). `prefers-reduced-motion`: show the first label statically. **Comment
  it clearly** as plausible-ordered, not event-driven (that's the deferred streaming spec).
- **`src/index.css`** — `.answer-table` (table + `<pre>` variants, small, monospace numerics,
  a highlighted-row hook `.answer-table tr.match` for later), warm-voice tweaks, a
  `prefers-reduced-motion` guard block if not already present.
- **`.claude/rules/src.md`** — add the "SPA may read `document_chunks` for source display
  only" exception (see *Architecture change*).

**Checkpoint (browser, signed in)**

- Ask a norm/cutoff-table question (e.g. AUDIT risk zones, PHQ-9 severity bands) → the answer
  shows the prose **and** a rendered table from the cited chunk with a page caption.
- A non-table answer is unchanged (no empty `<figure>`, no extra fetch).
- While a turn is pending, the status text cycles through the four stages, then the answer
  replaces it.
- "Copy" on a grounded answer yields the answer + a `Sources:` block with `Manual, p.N: "…"`
  lines; the fallback hint appears if the clipboard is blocked.
- The abstain card reads as a calm colleague, still amber, still offers "Choose another
  manual".
- `pnpm lint / test / test:functions / build` green; `run_evals.py --quick` green (sanity).

**Hard gate:** `/code-review` on the Phase-1 diff (focus: the new `document_chunks` read is
JWT-scoped and display-only; Markdown-table parsing can't XSS via chunk content — render as
text, never `dangerouslySetInnerHTML`). Report + stop.

## Phase 2 — Citation viewer v2

**Delivers:** opening a citation gives a navigable in-app view of the whole manual — scroll,
zoom, jump by page, and search the text — not one frozen page.

**Files**

- **`src/lib/api.ts`** — `manualText(versionId): Promise<{ page: number; content: string;
  section: string | null }[]>` — `supabase.from('document_chunks').select('page, content,
  section').eq('version_id', versionId).order('page')` under the caller client. Used for the
  search index (client-side).
- **`src/components/SourceSlideOver.tsx`** — rework:
  - Render **all pages** of the PDF, not just the cited one — lazily (render a page's canvas
    when it scrolls near the viewport; a lightweight IntersectionObserver, no virtualization
    library). Scroll to and flash-highlight the cited page + quote on open ("Found it on
    page N" caption for ~2 s).
  - **Zoom** control (a `scale` state, − / reset / + ; re-render visible pages on change).
  - **Prev / next page** buttons + a "page X of N" readout that updates on scroll.
  - **"Search this manual"** input: filter `manualText` by substring (case-insensitive),
    show a small results list (`p.N · …snippet…`), click → scroll to that page.
  - `Esc` closes the slide-over (wire the keydown here).
  - Keep the existing "couldn't pinpoint the passage" fallback and the pdf.js worker setup.
- **`src/index.css`** — styles for the page stack, zoom bar, search box + results, the
  "found it on page N" flash.

**Checkpoint (browser)**

- Open a citation → the slide-over scrolls to the cited page with the quote highlighted and a
  brief "Found it on page N".
- Scroll up/down through the entire manual; pages render as they come into view.
- Zoom in/out; the page re-renders crisply at the new scale.
- Type a term into "search this manual" → matching pages listed → click one → it scrolls
  there.
- `Esc` closes it. Works for a plain student on an active manual.
- Local sweep green.

**Hard gate:** `/code-review` on the Phase-2 diff (focus: lazy page rendering doesn't leak
canvases / observers on close; the search reads chunk text under the JWT only; large manuals
don't jank the main thread). Report + stop.

## Phase 3 — Around the answer

**Delivers:** a manual has a home page; the Ask empty state suggests questions; first-time
users get oriented; instruments have a visual identity; small keyboard + usage niceties land.

**Files**

- **`src/routes/Manual.tsx`** *(new)* — route `/manual/:versionId` (under `RequireAuth` +
  `Shell`). `getAskVersion` for metadata + `manualOutline(versionId)` (derive from
  `manualText`: distinct `section` with its first `page`, in page order). Shows: instrument
  monogram + name, edition / year / publisher, page count, a section outline list, and a
  primary **"Ask about this →"** → `/ask/:versionId`. If the version isn't
  active/visible, the friendly "not available" state (reuse Ask's).
- **`src/App.tsx`** — add the `/manual/:versionId` route.
- **`src/routes/Library.tsx`** — active rows link to `/manual/:id` (not `/ask/:id`). The
  sidebar quick-list (`Sidebar.tsx`) stays `/ask/:id` — the fast path for repeat use.
- **`src/lib/starters.ts`** *(new)* — `STARTERS: Record<string /* instrument slug */,
  string[]>` with 3–5 questions each for `pss`, `phq-gad7`, `audit` (+ a small generic
  fallback list). Authored to be genuinely useful ("What score indicates hazardous
  drinking?", "Which items are reverse-scored?", "What are the severity bands?").
- **`src/routes/Ask.tsx`** — on the empty state, render the starters for
  `version.instrument.slug` as clickable chips that set the composer draft (do not
  auto-submit). Add the `/` global shortcut: focus the composer unless an input/textarea is
  already focused.
- **`src/lib/api.ts`** — `getAskVersion` select gains `instrument:instruments(name, slug)`;
  `AskVersion.instrument` gains `slug`. `myQuestionsToday(): Promise<number>` —
  `query_log` count for the caller where `at >= <local start-of-day ISO>` (`head: true`,
  `count: 'exact'`).
- **`src/lib/instrument.ts`** *(new)* — `instrumentBadge(slugOrName): { initials: string;
  tint: string }` — initials from the name (PSS, PHQ, GAD, AUD…), tint from a fixed 6-colour
  palette hashed by slug. Used in `Library.tsx`, `Ask.tsx` locked header, `Manual.tsx`.
- **`src/components/FirstRunCard.tsx`** *(new)* — shown on `Library` when
  `localStorage['verbatim.onboarded']` is unset; one card: "Pick one edition. Ask a
  question. Get an answer quoted from that edition, with a page citation — or an honest 'not
  found in this version.'" Dismiss sets the flag. `try/catch` the storage access.
- **`src/components/Sidebar.tsx`** — a small "{n} questions today" line (from
  `myQuestionsToday`), quietly styled.
- **`src/components/SourceSlideOver.tsx`** / **`src/index.css`** — the citation-as-receipt
  micro-animation on the "Verified against source" row (`AnswerCard`), the padlock
  "click-shut" on `.ask-lock` mount, and a pass over the `[data-theme="dark"]` tokens for a
  warmer charcoal (not pure black). All motion behind `prefers-reduced-motion`.

**Checkpoint (browser)**

- Library row → `/manual/:id` shows metadata + a section outline + "Ask about this →" →
  lands in Ask for that version.
- Ask empty state shows instrument-specific starter chips; clicking one fills the composer.
- `/` focuses the composer from anywhere on the Ask screen.
- First load in a fresh browser shows the onboarding card once; dismiss, reload, it's gone.
- Instrument monograms/tints show in the Library and the locked Ask header.
- "N questions today" shows a plausible count.
- Dark mode looks warm, not black; the verified-row + padlock animations are subtle and
  respect reduced-motion.
- Local sweep green.

**Hard gate:** `/code-review` on the Phase-3 diff (focus: `localStorage` access is
try/caught; the `/` shortcut doesn't hijack typing; `myQuestionsToday` timezone handling;
route added correctly under auth). Report + stop.

## Deviations from spec

*(app-developer appends during Build, release-qa during Verify. "None" if nothing diverged.)*

### Phase 1 (app-developer)

- **Docling stores tables FLATTENED, not as grids — so "render a real `<table>`" is not
  achievable from the current corpus.** The cited chunk `content` for a `table_ref` chunk is
  a linearised string (`"<title>\n<rowLabel>, <colHeader> = <value>. …"`), not markdown.
  Reconstructing a grid from it is fragile and lossy. **Implemented instead:** a labelled
  `From a table · p.N` excerpt showing the flattened text in a `<pre>` block + a "See it on
  the source page →" jump (the real grid is legible in the PDF, and more so after Phase 2's
  viewer). `parseMarkdownTable()` (`src/lib/tables.ts`, unit-tested) is kept and used first,
  so a future re-ingest that stores real grid text (ingest-v2, e.g. Docling
  `table.export_to_html()` / a `document_chunks.table_html` column) renders as a `<table>`
  with **no further SPA change**. → added to `docs/backlog.md`.
- **Abstain card warmed:** heading "Not found in this version" → "Not in this edition";
  body → "This version of the manual doesn't cover that. Try another edition from the
  library, or rephrase your question."; button "Choose another manual →" → "Browse the
  library →". Still amber, still `AnswerCard`.
- **`AnswerProgress` is client-timed (2.6 s/label), not event-driven** — commented as such.
  `prefers-reduced-motion` shows a single static label; a global
  `@media (prefers-reduced-motion: reduce)` guard was added to `src/index.css` (there was
  none).
- **`.claude/rules/src.md`** gained the "SPA may read `document_chunks` for source display
  only" exception (Architecture change).
- **`citedChunkContent` needs no `versionId`** — chunk ids are globally-unique uuids and
  `document_chunks_select_via_version` RLS gates the read, so `AnswerCard` (which has no
  `versionId` prop) can call it directly with just the cited chunk ids.
- **Checkpoint (browser, `/history` — LLM quota-blocked so no live `/ask`):** a grounded
  GAD-7 answer with a `table_ref` citation renders the excerpt + "See it on the source page
  →" + a working "Copy" (→ "Copied" / "Press ⌘/Ctrl-C" fallback); the abstain card reads
  warmly. `tsc` / 17 unit (5 new) / lint / build / 37 deno all green.
