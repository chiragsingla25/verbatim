# Spec addendum — Verbatim v1.1.2: password reset + infra-fix bundle

Build contract for app-developer, extending v1 / v1.1 / v1.1.1 (all frozen build records).
Same architecture, stack, deployment — Vite + React SPA on GitHub Pages, Supabase Postgres +
pgvector + Auth + Storage + Edge Functions. **No `/ask` pipeline change, no new service.**
Phases are hard gates: implement one, run its checkpoint, stop for approval.

Delivery model: single generalist developer + a fresh-context `/code-review` at each phase
boundary — Phase 1 touches auth, Phase 2 touches an RLS policy + three Edge Functions.

---

## Scope

Two unrelated tracks, user-confirmed 2026-09-10:

1. **Forgot-password flow** — the only auth flow still missing. Signup + email confirmation
   work end to end on the live site (Supabase built-in mail); there is no password reset
   anywhere.
2. **Infra-fix bundle** — seven XS items of debt recorded across three release-qa Verify
   passes, batched into one CI/deploy cycle.

**Out of scope** (stay deferred): per-PR full-RAGAS eval gating; edition comparison; batch
Q&A; reranker; citation export; Library search/filter; monitoring / Langfuse; Supabase Pro.

## Intake decisions (2026-09-10)

- **Recovery-link landing:** a dedicated public **`/reset-password`** route that listens for
  supabase-js's `PASSWORD_RECOVERY` event — not an overloaded `/auth/callback` branch.
- **After a new password is set:** straight into the app (`updateUser({ password })` leaves a
  full session) — matches how signup-confirm already lands the user signed in.
- **Per-PR eval gating:** deferred. v1.1.2 stays an all-XS, low-risk bundle.

## Prior art & scope rationale

Password reset is the most standardized auth flow there is; Supabase documents the exact
shape and v1.1.2 copies it verbatim:

```
"Forgot password?" link  →  request screen  →  supabase.auth.resetPasswordForEmail(email,
  { redirectTo: <app>/reset-password })  →  recovery email  →  link lands on /reset-password
  →  supabase-js fires PASSWORD_RECOVERY  →  set-new-password form  →
  supabase.auth.updateUser({ password })  →  navigate('/')
```

**Table stakes** (all in): the link on SignIn; a request screen that shows the same success
message whether or not the address is registered (no account-existence leak); a
set-new-password screen; an expired/used-link message. **Deliberately skipped as overkill for
a pilot:** security questions, SMS/2FA reset, a password-strength meter beyond the browser
default, "your password was changed" notification emails, custom rate-limit UX (Supabase
throttles `resetPasswordForEmail` server-side).

The infra bundle is not a feature — it is recorded debt (`specs/2026-09-07-verbatim.md`
"Verify pass", `specs/2026-09-09-verbatim-v1.1.md` and `specs/2026-09-10-verbatim-v1.1.1-*`
"Deviations"). Batched to amortize one review + ship.

## Phased build plan

### Phase 1 — Forgot-password flow

**Files**
- `src/routes/ForgotPassword.tsx` **(new)** — public route `/forgot-password`, `AuthShell`.
  Email field → `supabase.auth.resetPasswordForEmail(email, { redirectTo:
  ${window.location.origin}${import.meta.env.BASE_URL}reset-password })`. On success show a
  "Check your email" panel (mirror `SignUp`), **regardless of whether the address exists** —
  do not surface a "no such user" error. A back link to `/signin`.
- `src/routes/ResetPassword.tsx` **(new)** — public route `/reset-password`, `AuthShell`.
  On mount, subscribe to `supabase.auth.onAuthStateChange`; when the event is
  `PASSWORD_RECOVERY` (or a session is already present from the parsed hash), render a
  "Set a new password" form (new password + confirm, `autoComplete="new-password"`, min length
  guard matching Supabase's policy). Submit → `supabase.auth.updateUser({ password })` →
  `navigate('/', { replace: true })`. If after ~4 s there is no session and no
  `PASSWORD_RECOVERY` event, show "This reset link has expired or was already used." + a link
  to `/forgot-password` (mirror `AuthCallback`'s `slow`). Unsubscribe on unmount.
- `src/components/AuthShell.tsx` — make `active` optional (`active?: 'signin' | 'signup'`);
  when absent, render the panel without a highlighted tab (the seg control may still show as
  plain nav, or be hidden — implementer's call, keep it minimal).
- `src/routes/SignIn.tsx` — a "Forgot password?" `<Link to="/forgot-password">` under the
  password field.
- `src/App.tsx` — add `/forgot-password` and `/reset-password` as public routes.
- `src/lib/auth.tsx` — only if needed: confirm the global `onAuthStateChange` handler does
  not redirect a `PASSWORD_RECOVERY` session away from `/reset-password` before the user sets
  a password. Expect no change (a recovery session is a normal session; `/reset-password` is
  public so `RequireAuth` never runs).

**Checkpoint (live site, real email):**
- `/signin` shows "Forgot password?" → `/forgot-password`; submitting a **registered**
  address shows "Check your email" and a recovery email arrives.
- Submitting an **unregistered** address shows the **same** "Check your email" screen (no
  account-existence leak) — verify no error is rendered.
- Clicking the emailed link lands on `/reset-password` with the set-password form; a valid
  new password → lands in the library, signed in; the new password works on a fresh
  `/signin`, the old one does not.
- Opening a **stale** `/reset-password` (no hash) or a **reused** link shows the
  expired-link message with the `/forgot-password` link.
- `pnpm lint` + `pnpm test` + `pnpm build` green.

### Phase 2 — Infra-fix bundle

**Files**
- `.github/workflows/deploy.yml` — `actions/checkout` with

  `name ~ '…{36}…'` + `(split_part(name,'/',2))::uuid` that can raise on a crafted name.
  Keep the existing `manuals_select_contrib` (contributor broad read) untouched.

- `supabase/functions/_shared/http.ts` **(new)** — `jsonResponse(status, body, opts?)` +

  unchanged.
- `src/lib/api.ts` `listVisibleVersions` — drop `ingest_jobs(state, created_at)` from the

  rows). `RawVersionRow` loses `ingest_jobs`.

**Checkpoint (script + browser):**

- `run_evals.py`: with a deliberately bad `SUPABASE_ANON_KEY`, the run exits non-zero with a

## Deviations from spec

*(app-developer appends during Build, release-qa during Verify. "None" if nothing diverged.)*

### app-developer — Build

- **[phase 1] `ResetPassword` gates the form on `recovered || (!!session && HAD_RECOVERY_HASH)`.**
  `HAD_RECOVERY_HASH` is captured at module load (before supabase-js's `detectSessionInUrl`
  strips the hash) so a signed-in user who merely navigates to `/reset-password` gets the
  expired-link message, not a password-change form. Spec said "listen for `PASSWORD_RECOVERY`";
  this adds the hash-capture fallback because the event can fire before the component mounts.
- **[phase 1] `ForgotPassword` surfaces network / 429 errors** ("Couldn't send…" / "Too many
  requests…") instead of always showing the confirmation. Supabase already returns success
  for unknown addresses, so this doesn't leak account existence — driven by the phase-1
  `/code-review`.
- **[phase 1] Extracted `CheckYourEmail.tsx` + `useSlowFlag.ts`** and refactored `SignUp` /
  `AuthCallback` onto them (phase-1 `/code-review` reuse findings).
- **[phase 2] `run_evals.py` exits `3`, not the spec's `2`, on a terminal `/ask` 401/403** —
  and `ci.yml` gained an `elif` that fails the job with an `::error::`. Conflating an
  auth/config break with the *tolerated* quota warning (exit 2) would hide a real CI failure.
  The catch also covers the `eval_user_token` grant path, narrowed to `HTTPStatusError` with
  status 401/403.
- **[phase 2] `ingest-dispatch`'s `OBJECT_RE` was also tightened** to a real UUID (same fix,
  same file touched for `_shared/http.ts`).
