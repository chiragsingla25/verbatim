# Verbatim v1.4 — chat-first (revert two v1.3 UI decisions)

## Prior context

v1.3 "usefulness + UI warmth" (`specs/2026-09-12-verbatim-v1.3-usefulness.md`, shipped
`d86859c`) added a manual detail page as an intermediate step between the Library and Ask,
and rendered a cited table's content inline in the answer (`TableExcerpt`). Live usage
turned up that both read worse than the flow they replaced:

1. **Manual detail page** (`/manual/:versionId`) makes picking a manual a two-click journey
   (Library → manual page → "Ask about this manual →" → Ask) where v1 and v1.2 were one
   click straight into the chat. The page's content (edition/pages/publisher, section
   outline) isn't worth the extra hop.
2. **In-chat table excerpt** (`TableExcerpt` in `AnswerCard.tsx`, fed by
   `citedChunkContent()`) puts a flattened `<pre>` block of raw chunk text directly in the
   chat whenever a cited chunk has a `table_ref`. The user's read: the earlier flow — prose +
   numbered citation chips, with the actual source page opened in the right-side citation
   viewer on click — was the better design. The citation viewer (v1.3 Phase 2: full-document
   scroll, zoom, search) already does this job; the inline excerpt duplicates it worse (flat
   text, no context, no zoom).

This is a **pure UI reversion + simplification** on top of the shipped v1.3 SPA. No pipeline,
prompt, migration, or Edge Function change — the answer's `citations` shape is untouched;
only how the SPA renders it changes.

## Scope

1. Library rows link straight to `/ask/:versionId` again (pre-v1.3 behaviour). The
   `/manual/:versionId` route, `Manual.tsx`, and the outline-building code are **deleted**,
   not left dormant (per intake: the metadata that page showed — edition/year/publisher — is
   already visible in the Library's own row; only the page-count + section outline is lost,
   and no other screen shows it today).
2. A grounded answer goes back to: prose with inline highlighted quotes + a row of numbered
   citation chips (`[1] p.3`, `[2] p.6`, …) + Copy. **No chunk/table content renders inside
   the chat.** A table-cited chunk's chip looks identical to any other page citation (per
   intake) — the citation viewer already reveals it's a table once opened. `TableExcerpt`,
   `citedChunkContent()`, `parseMarkdownTable()` / `src/lib/tables.ts`, and the `.answer-table`
   CSS are **deleted outright** (per intake — not left dormant).
3. The **citation viewer itself (v1.3 Phase 2: full-document scroll, zoom, "search this
   manual", "Found on page N") is unchanged and stays** — clicking any citation chip opens it
   exactly as it does today, landed on that citation's page. `manualText()` in `api.ts` is
   kept (the viewer's search still needs it) — only `manualOutline()` / `OutlineItem` (used
   solely by the now-deleted Manual page) go.

## Out of scope

- Any change to `/ask` pipeline, prompts, `_shared/schema.ts`, or `query_log` shape.
- Any change to `SourceSlideOver.tsx` itself (scroll/zoom/search stay exactly as built).
- The accuracy-mvp facts block (`__facts__` citations) — a `Document metadata` citation still
  renders as today; this spec only removes the *table* excerpt path.
- Starter questions, instrument monograms, first-run card, `/` shortcut, "N questions today"
  — all other v1.3 Phase 3 additions are untouched.
- Re-adding a "manual info" affordance elsewhere (considered and declined at intake — the
  Library row already carries edition/year; nothing else currently needs a home).

## Architecture change

None. Pure SPA diff — same components, same API surface minus the two removed functions,
same routes minus one. No new dependency.

## Phase 1 — Library → Ask, straight through

**Files**
- `src/routes/Library.tsx` — row links go back to `/ask/${v.id}` (from `/manual/${v.id}`).
- `src/App.tsx` — remove the `/manual/:versionId` `<Route>`.
- `src/routes/Manual.tsx` — **delete the file**.
- `src/lib/api.ts` — delete `manualOutline()` and the `OutlineItem` type. Leave `manualText()`
  and `ManualTextRow` — the citation viewer's search still calls them.
- Remove any now-unused imports (`instrumentBadge` in `Manual.tsx` goes with the file;
  confirm `Library.tsx` still needs its own `instrumentBadge` import for the row monograms —
  it does, that stays).

**Checkpoint (browser, signed in):** clicking a manual in the Library goes straight to
`/ask/:id` (no intermediate page). Typing `/manual/<id>` in the address bar 404s (SPA
fallback → no matching route). `pnpm build` has no dangling import errors. Sidebar's own
quick-list (already `/ask/:id`, untouched by v1.3) is unaffected either way.

## Phase 2 — Chat shows citations, not chunks

**Files**
- `src/components/AnswerCard.tsx` — in `GroundedAnswer`: delete the `chunks` state, the
  `citedChunkContent` effect, the `tableChunks` derivation, the `<TableExcerpt>` render call,
  and the `TableExcerpt` function itself. The citation chips loop (`pageCites.map(...)`)
  and the `onCite(c.page, c.quote)` wiring are **unchanged** — a table-cited chunk's chip
  reads `[i+1] p.{page}` exactly like any other (per intake, no visual hint). Confirm the
  `factsCited` / "Document metadata" chip path (accuracy-mvp) is untouched — that's a
  separate feature.
- `src/lib/api.ts` — delete `citedChunkContent()` and the `CitedChunk` type.
- `src/lib/tables.ts` + `src/lib/tables.test.ts` — **delete both files** (only consumer was
  `TableExcerpt`).
- `src/index.css` — remove `.answer-table`, `.answer-table-scroll`, `.answer-table pre`, and
  the table-specific `figcaption` rules added in v1.3 Phase 1. Leave `.cite-chip` and
  everything else untouched.

**Checkpoint (browser, against a real answer citing a table — e.g. "What is the score range
of the GAD-7?" on the PHQ/GAD-7 manual, known from the eval corpus to cite `#/tables/1`):**
the answer renders as prose + a citation chip row only — no `<pre>` block, no "From a table"
caption anywhere in the chat. Clicking that citation chip opens the (unchanged) citation
viewer landed on the cited page, where the table content is visible in the real PDF. A
non-table citation behaves identically to before (no regression — it never rendered an
excerpt anyway). `pnpm test` drops the 5 `tables.test.ts` cases (21 → 16); `pnpm build` and
`pnpm lint` stay clean.

## Deviations from spec

- Both phases were small and unambiguous after the intake decisions, so they were built and
  committed together in one sitting rather than stopping at a Phase 1 gate (per the
  build-request's own instruction — a small two-phase reversion).
- One thing not explicitly named in the spec: deleting `Manual.tsx` also orphaned its
  page-specific CSS (`.manual-hero`, `.manual-facts`, `.manual-superseded`, `.manual-ask`,
  `.manual-outline` + children). Removed alongside the `.answer-table` rules, consistent with
  the "delete outright" intake decision for both features.
- **Checkpoint results:** Library rows link to `/ask/:id` again (verified — one click, no
  intermediate page); a direct hit on the old `/manual/:id` URL falls through to the Library
  route (no crash, no dead page — confirmed via full navigation, not just client-side
  routing). The known table-citing answer ("What is the score range of the GAD-7?") now
  renders as prose + `[1] p.6 [2] p.3` + Copy only — no `<pre>`/`<table>` in the chat;
  clicking `[2] p.3` opens the (unmodified) citation viewer landed on "Page 3 of 9", the
  cited page. Local sweep: lint clean (1 pre-existing warning), unit tests 16/16 (21 → 16,
  the 5 `tables.test.ts` cases removed as expected), build clean (197 modules, down from 199).
