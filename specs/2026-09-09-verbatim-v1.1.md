# Spec addendum — Verbatim v1.1

Build contract for app-developer, extending v1 (`specs/2026-09-07-verbatim.md`, now frozen as
the v1 build record). Same architecture, stack, and deployment — Vite + React SPA on GitHub
Pages, Supabase Postgres + pgvector + Auth + Storage + Edge Functions, the deterministic RAG
pipeline. **No new architecture pattern, no new service, no `/ask` pipeline change.** Phases
are hard gates: implement one, run its checkpoint, stop for approval.

Delivery model: single generalist developer + a fresh-context review gate (`/code-review`) at
each phase boundary — this touches RLS and adds a `SECURITY DEFINER` admin surface, so it is
quality-sensitive.

---

## Scope

Three features from `docs/backlog.md`, user-confirmed 2026-09-09:

1. **Session history / "My answers"** — a `/history` screen: list and reopen past Q&A.
2. **Manual archive & supersede** — take a published version offline (reversible); mark one
   edition as superseding another.
3. **Admin console** — a `/admin` surface (Users · Manuals · Activity), replacing every
   "an admin edits the DB by hand" step.

**Out of scope for v1.1** (stay deferred): edition-comparison, batch Q&A, reranker,
monitoring / Langfuse, the frontend polish nits, and the infra-fix bundle (`deploy.yml`
`head_sha` pin, `run_evals.py` traceback, UUID-regex tightening) — those ride a later PR.

## Intake decisions (2026-09-09)

- **Archive authority:** admin only. Contributors upload + review; taking a live manual down
  is an admin action.
- **Role management:** the admin console has **full role control**, including granting `admin`.
  The only guard: an admin **cannot change their own `profiles.role`** (self-lockout
  protection), enforced server-side in the RPC.
- **History:** list + reopen the **stored** answer (no LLM call), plus a **"Re-ask"** button
  that re-runs the question **against the same `version_id`** the entry was logged against —
  shown only when that version still resolves and is `active`, hidden otherwise. No
  user-delete: `query_log` is the eval corpus and has no update/delete policy by design.
- **Admin console:** three tabs — Users, Manuals, Activity (read-only `audit_log` feed).

## Deviations from v1

- **[v1.1] Admin role management via UI, including granting `admin`.** v1's Phase 1 clarify
  said "no admin UI in v1 … admin sets other users to contributor via a direct `profiles`
  update". v1.1 reverses that deliberately: `admin_set_role` (SECURITY DEFINER, admin-gated)
  is the supported path, with a self-change guard. The direct SQL path still works.

## What v1 already provides (no change needed)

- `query_log` stores per `/ask`: `question, answer, abstained, citations` (jsonb
  `{chunkId,page,quote}`), `retrieved` (jsonb), `version_id`, `at` — a complete
  `AnswerResult`. History re-renders with **zero LLM calls**. RLS
  `query_log_select_self_or_admin` already allows self-read; indexes on `user_id`, `at desc`.
- `manual_versions.status` CHECK already includes `'archived'`; `supersedes_id` (self-FK)
  already exists.
- `document_chunks_select_via_version` and the `manuals_select_active_source` storage policy
  (`20260908170000`) both gate on `status = 'active'`, so archiving a version **automatically**
  hides its chunks and source PDF from students and makes `match_chunks` / `/ask` abstain for
  them — **verified in the Phase 2 checkpoint, not re-implemented.**
- `profiles` has no `email` (it's in `auth.users`) → the admin user list needs a
  `SECURITY DEFINER` RPC. `auth_role()` is the role helper; `useAuth()` exposes
  `{ session, role, loading }`; `App.tsx` has `RequireAuth` / `RequireRole`.
- RPC pattern to copy: `publish_manual_version` (`20260908140200_publish_rpc_definer.sql`).
- Reusable UI: `Answer` + `renderWithCitations` in `src/routes/Ask.tsx`; lazy
  `SourceSlideOver`; `Sidebar` / `MobileTopBar`.

## Phased build plan

### Phase 1 — Session history / "My answers"

- `src/components/AnswerCard.tsx` (new) — extract `Answer` + `renderWithCitations` verbatim
  from `src/routes/Ask.tsx`; `Ask.tsx` imports it (pure refactor).
- `src/lib/api.ts`:
  - `listMyHistory({ versionId?, before?, limit = 25 })` — `query_log` select under caller
    RLS, `order('at', { ascending: false })`, keyset paginate on `at < before`. Returns
    `{ id, question, answer, abstained, citations, retrieved, versionId, at }`.
  - `historyManuals()` — distinct `version_id`s in the caller's `query_log`, joined to
    `manual_versions(title, instrument(name))`, for the filter dropdown.
- `src/routes/History.tsx` (new) — `/history`, `RequireAuth`. Newest-first list (question,
  answer snippet, manual label, relative date); manual `<select>` filter; "Load more". A row
  expands to a full `<AnswerCard>` built from the stored row + the lazy `SourceSlideOver`
  (same wiring as `Ask.tsx`). Per-row **"Re-ask →"**: `getAskVersion(row.versionId)`; if it
  resolves and `status === 'active'`, link to
  `/ask/${row.versionId}?q=${encodeURIComponent(row.question)}`; else omit.
- `src/routes/Ask.tsx` — read `?q=` on mount, prefill the composer, do **not** auto-submit.
- `src/App.tsx` — `/history` route in `RequireAuth` + `Shell`.
- `src/components/Sidebar.tsx` — "My answers" `NavLink` for all signed-in users (with
  `onNavigate` for the mobile drawer).

**Checkpoint:** signed in, `/history` lists past Q&A; the filter narrows it; "Load more"
pages; expanding a row shows the answer + working citation slide-over with **no `/ask`
network call**; "Re-ask" navigates to Ask with the question prefilled for an active version
and is absent for an archived / removed one; `Ask.tsx` unchanged in behaviour.

### Phase 2 — Manual archive & supersede

- `supabase/migrations/20260909NNNNNN_manual_lifecycle.sql` (new) — three `SECURITY DEFINER`,
  `set search_path = public` RPCs (model: `publish_manual_version`):
  - `archive_manual_version(p_version_id uuid)` — authed; `auth_role() = 'admin'`; version
    exists and `status = 'active'`; → `status = 'archived'`; `audit_log` `action='archive'`.
  - `republish_manual_version(p_version_id uuid)` — same authz; `status = 'archived'` →
    `'active'`; `audit_log` `action='unarchive'`.
  - `set_supersedes(p_version_id uuid, p_supersedes_id uuid)` — admin; both versions exist and
    share `instrument_id`; `p_supersedes_id <> p_version_id`; `NULL` clears; set the column;
    `audit_log` `action='supersede'`.
  - `revoke … from public, anon; grant execute … to authenticated` on all three.
- `src/lib/api.ts` — `archiveVersion(id)`, `republishVersion(id)`, `setSupersedes(id, target |
  null)` wrappers (throw on error). `listVisibleVersions` / `getAskVersion` also select
  `supersedes_id`; add a resolved `supersededBy` (the version whose `supersedes_id` points at
  this one).
- `src/routes/Library.tsx` + `src/routes/Ask.tsx` locked header — a small read-only
  "superseded by <title>" hint (links to that version's Ask) when present.
- **No policy migration** — a comment in the migration notes that
  `document_chunks_select_via_version` + `manuals_select_active_source` already gate archived
  versions; the checkpoint proves it.

**Checkpoint (script + browser):** as admin, `archiveVersion` on an active version →
- a fresh student's Library omits it; `/ask` against it abstains; a direct `document_chunks`
  select and `match_chunks` both return 0; its `source.pdf` signed URL is denied to the
  student;
- the student's existing `/history` entries for it still render the stored answer; "Re-ask"
  is now hidden;
- `republishVersion` restores all of it;
- `set_supersedes(newer, older)` → the older row / Ask header show "superseded by <newer>";
- a non-admin calling any of the three RPCs is rejected.

### Phase 3 — Admin console

- `supabase/migrations/20260909NNNNNN_admin_rpcs.sql` (new) — `SECURITY DEFINER`, each body
  re-checks `auth_role() = 'admin'`:
  - `admin_list_users()` → `id`, `email` (from `auth.users`), `role`, `created_at`,
    `last_sign_in_at`, ordered by `created_at`.
  - `admin_set_role(p_user_id uuid, p_role text)` — `p_role in
    ('student','contributor','admin')`; **reject when `p_user_id = auth.uid()`**
    (`errcode 'check_violation'`, "cannot change your own role"); update `profiles.role`;
    `audit_log` `action='role_change'`, `meta = {target, from, to}`.
  - `admin_list_activity(p_limit int default 100)` → recent `audit_log` rows + actor email,
    newest first.
  - grants to `authenticated`.
- `src/lib/api.ts` — `adminListUsers()`, `adminSetRole(userId, role)`, `adminListActivity()`,
  `adminListAllVersions()` (admin RLS already returns every `manual_versions` row — select it
  + latest `ingest_jobs.state` + instrument name). Reuse `getReviewData` / `archiveVersion` /
  `republishVersion` / `setSupersedes`.
- `src/routes/Admin.tsx` (new) — `/admin`, `RequireRole roles={['admin']}`. Tab in the URL
  (`?tab=users|manuals|activity`):
  - **Users:** table (email · role · joined · last seen), per-row role `<select>` →
    `adminSetRole`; the current admin's own row `<select>` disabled with a tooltip.
  - **Manuals:** every version (instrument · title · edition · status pill · ingest state);
    per-row actions — "Review →" (`/review/:id`), "Archive" / "Re-publish", "Supersedes…"
    picker (same-instrument versions).
  - **Activity:** `adminListActivity` list — actor · action · target · relative time.
- `src/App.tsx` — `/admin` route in `RequireRole roles={['admin']}` + `Shell`.
- `src/components/Sidebar.tsx` — "Admin" `NavLink`, rendered only when `role === 'admin'`.

**Checkpoint (browser as `singlachirag25@gmail.com`):** Users tab promotes a student to
`contributor` (they see the Upload nav after a reload) and can set `admin`; the admin's own
role `<select>` is disabled and `admin_set_role` on self is rejected server-side; Manuals tab
archives / re-publishes a version and sets a supersede link; Activity shows the
`role_change` / `archive` / `supersede` entries; a `contributor` hitting `/admin` gets "Not
available", and a direct `adminListUsers()` call as non-admin errors.

## Verification step (whole addendum)

Hand to release-qa when all three phases pass their own checkpoints:

1. **AuthZ / RLS:** a non-admin cannot invoke any `admin_*`, `archive_*` / `republish_*` or
   `set_supersedes` RPC; `admin_set_role` cannot change the caller's own row; an archived
   version is fully invisible to students across Library, `/ask`, `document_chunks`,
   `match_chunks`, and `source.pdf`.
2. **History:** rows are self-only (RLS); displaying an entry makes **no `/ask` call**;
   "Re-ask" appears only for a resolvable active version.
3. **No pipeline regression:** `/ask`, embeddings, `match_chunks`, and the eval suite are
   untouched — `python evals/run_evals.py --quick` stays green.
4. **Local sweep:** `pnpm lint` + `pnpm test` + `pnpm test:functions` + `pnpm build` green;
   Deno tests for the pure authz branches of the new RPCs where practical, else the live
   checkpoint scripts cover them.
5. **Ship:** unchanged — merge to `main` → CI → `deploy.yml` → Pages; `supabase db push` for
   the two migrations; no new Edge Function.

## Deviations from spec

*(app-developer appends during Build, release-qa during Verify. "None" if nothing diverged.)*

- **[phase 1] `AnswerCard.result` prop is `Pick<AnswerResult, 'answer'|'citations'|'abstained'>`,
  not the full `AnswerResult`.** The plan said "extract verbatim". Widening the prop lets
  `/history` pass a `HistoryEntry` without fabricating `versionId`/`retrieved`; the component
  body is byte-identical and Ask.tsx still passes a full `AnswerResult`. No behaviour change.
- **[phase 1] The pure row → `HistoryEntry` transform lives in a new `src/lib/history.ts`, not
  in `src/lib/api.ts` as planned.** `src/lib/supabase.ts` throws at import when `VITE_*` env
  vars are absent (CI), so anything transitively importing `api.ts` can't be unit-tested there.
  `history.ts` has no supabase import; `api.ts` re-exports `HistoryEntry` and imports the
  transform. Driven by the phase-1 `/code-review` test-coverage finding.
- **[phase 1] Keyset pagination uses a compound `(at, id)` cursor, not `at` alone** (plan said
  `at < before`). `query_log.at` is not unique; `/code-review` flagged that `at`-only could skip
  rows sharing a timestamp at a page boundary. `listMyHistory`'s `before` param is now
  `{ at, id }`.
- **[phase 1, pre-existing] `<link rel="icon" href="./favicon.svg">` in `index.html` 404s on
  deep routes** (`/verbatim/ask/…`, `/verbatim/history` resolves fine; `/verbatim/ask/x` →
  `/verbatim/ask/favicon.svg`). Not introduced by v1.1 — spotted during Phase 1 browser
  testing. Cosmetic; add to the polish backlog (use an absolute `%BASE_URL%favicon.svg`).
- **[phase 2] A follow-up migration `20260909100100_supersedes_guards.sql` was added after the
  phase-2 `/code-review`**: a partial unique index on `supersedes_id` (a version can be
  superseded by at most one other) and a direct 2-cycle reject in `set_supersedes`. The plan
  had neither; the review flagged that the reverse-lookup `.maybeSingle()` could error on a
  duplicate-superseder misconfiguration.
- **[phase 2] A persistent `chiragsingla25+admin@gmail.com` admin test account was created**
  for the phase-2 checkpoint (and reused in phase 3). The owner's real admin account
  (`singlachirag25@gmail.com`) has no test password on file. Password:
  `verbatim-admin-fixed-12345`; role `admin`, email confirmed.
- **[phase 2] `getAskVersion` now fires a second query per Ask load** (the superseder
  reverse-lookup), run in parallel with the version fetch via `Promise.all`. The plan
  anticipated "an extra query"; this is the refined form.
- **[phase 2] The spec's "no RLS policy change needed" claim held.** The phase-2 checkpoint
  proved a student loses Library visibility, `document_chunks`, `match_chunks`, and the
  `source.pdf` signed URL for an archived version purely from the existing `status='active'`
  gates in `document_chunks_select_via_version` and `manuals_select_active_source`.
- **[phase 3] Manuals tab needs no RPC** (plan floated `adminListAllVersions()` as maybe an
  RPC). Admin RLS on `manual_versions` / `ingest_jobs` already returns every row, so a plain
  `supabase.from('manual_versions').select(… ingest_jobs(state, created_at))` works; the client
  reduces to the latest ingest state.
- **[phase 3] Extracted `src/lib/format.ts`** (`relDate`, `errMessage`) — `History.tsx`'s
  local `relDate` and the repeated `e instanceof Error ? …` string now live there. Driven by
  the phase-3 `/code-review` reuse finding.
- **[phase 3] Unscoped `.r-name` / `.r-title` / `.r-sub` from `.lib-row`** so the admin Manuals
  rows stack the same way. Library re-verified unaffected.
- **[phase 3] `RequireRole`'s "Not available" copy is now role-aware** ("…grant you the admin
  role" for `/admin`, "…contributor role" for `/upload` and `/review`) instead of always
  saying "contributor".

### release-qa — Verify pass (2026-09-09)

Local sweep green (`lint` 0 warnings new / `test` 10 / `test:functions` 18 / `build` 0). Quick
eval suite green against the deployed `/ask`: 100% abstention accuracy (7 cases), 4/4
cross-version isolation, zero leaks — pipeline unregressed (no Edge Function change in v1.1).
Live authz probes against `pisnrzifesroatzisamw` confirmed: no non-admin can invoke any
`admin_*` / `archive_*` / `republish_*` / `set_supersedes` RPC; `admin_set_role` rejects
self-change and non-whitelist roles; an archived version is invisible to a student across
Library, `document_chunks`, `match_chunks`, and the `source.pdf` signed URL while their own
`query_log` history for it still renders; the compound `(at, id)` keyset cursor neither skips
nor repeats a row across a page boundary.

Two gaps were found and fixed in this pass:

- **[release-qa] `listMyHistory` / `historyManuals` relied purely on
  `query_log_select_self_or_admin` RLS with no explicit `user_id` filter.** That policy is
  *self-or-admin*, so for an admin the `/history` "My answers" screen listed **every user's**
  questions (verified live: 4 distinct `user_id`s returned). Free-text user questions are
  private. Fixed by adding `.eq('user_id', <caller>)` to both queries (`src/lib/api.ts`,
  new `currentUserId()` helper). Re-probed: admin now sees only their own rows.
- **[release-qa] The v1 policy `manual_versions_update_owner_or_admin` let a contributor run a
  direct PostgREST `UPDATE` on any row they created, with no column/value restriction.** A
  contributor could set `status='active'` on their own `pending` version — self-publishing an
  unreviewed manual, bypassing `publish_manual_version` — or flip `status` to
  `archived`/`active` directly, bypassing the admin-only `archive_manual_version` /
  `republish_manual_version` RPCs (the spec's "archive = admin only" decision). Verified live:
  the direct UPDATE succeeded (1 row, `pending → active`). Pre-existing in v1's policy but
  surfaced by v1.1's admin-only lifecycle RPCs and its self-publish implications. Fixed by
  new migration `20260909120000_manual_versions_update_admin_only.sql` — drops the contributor
  branch (no client path needs it; every contributor mutation goes through a SECURITY DEFINER
  RPC that runs as owner and is unaffected by RLS). **Must be applied (`supabase db push`)
  and re-probed before Ship** — CI/`deploy.yml` do not apply migrations.
