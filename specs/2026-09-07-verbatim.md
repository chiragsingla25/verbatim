# Spec — Verbatim v1

Build contract for app-developer. Decisions and rationale are in `docs/proposal.md`; this file is
what "done" is measured against. Phases are hard gates — implement one, report what you verified,
stop for approval.

---

## Prior art & scope rationale

Comparable products and what this build takes / leaves (full table in `docs/proposal.md`):

- **NotebookLM** — take: inline per-claim citations that open the source; "answers only from
  sources" stance. Leave: audio overviews, collab.
- **Humata / PDF.ai** — take: page-level citations, a multi-doc library. Leave: team seats, export.
- **Mintlify / GitBook / ReadMe "Ask AI"** — take: a version switcher that scopes both search and
  chat (→ the locked version selector). Leave: docs authoring.
- **Harvey / CoCounsel** — take: answer-to-source traceability, explicit abstention, "verify
  against source" framing. Leave: the N-questions × M-docs table (deferred batch Q&A).
- **Pearson Q-global / PARiConnect** — "qualified user" gating not needed for a public-domain
  corpus with no client data.

**Novelty:** no product does version-scoped Q&A over psychological test manuals → the
`cross-version-leak` eval is a required, blocking check.

## Guiding priorities (v1)

1. Works end to end on free, open-source infrastructure.
2. Correctness over latency — 5–15 s/answer (hosted open model) or 30–90 s (local Ollama) is fine.
3. Purely-OSS-capable — every model and all app code is OSS; the LLM endpoint is one env var from
   self-hosted Ollama. Top-tier accuracy is **not** a v1 goal (agentic retrieval comes later).

## Out of scope for v1

Reranker · planner–orchestrator / adaptive routing · edition-comparison ("what changed") · score /
CI / RCI calculators · quizzes / study tracking · workspaces & shared annotations · APA citation
generator & export · SSO / MFA / step-up auth · PDF sanitisation & malware scan · two-person
review · restricted-manual tier & per-manual access grants · instrument catalogue · batch Q&A ·
client-score entry · self-hosted Langfuse · commercial/licensed manuals (v1 corpus is
**public-domain instruments only**).

## System shape

- **Vite + React SPA** on **GitHub Pages** at `<user>.github.io/verbatim/` — bundler `base` and
  router `basename` set to `/verbatim/`. Talks to Supabase directly with the anon key (RLS
  enforces everything).
- **Supabase free tier** — Postgres + **pgvector** + Auth + Storage + Edge Functions (Deno).
- **Supabase Edge Functions** hold server secrets: `/ask` (the pipeline) and `/ingest-dispatch`
  (Storage webhook → GitHub `repository_dispatch`).
- **GitHub Actions** runs **Docling** for ingestion; also runs CI and a keep-warm cron.
- **LLM** — any OpenAI-compatible endpoint (`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`).

### Vector store — it IS Supabase Postgres

There is **no separate vector database.** `pgvector` is a Postgres extension; embeddings live in
the same database as the relational data. `document_chunks.embedding` is `vector(384)`
(`gte-small`). Retrieval is a SQL function using the cosine operator (`<=>`) with an **HNSW**
index. The same RLS policies cover those rows — version isolation is a row-level policy, with
nothing to sync between a relational DB and an external vector store.

### Data model (Supabase Postgres)

| Table | Key columns | RLS |
|---|---|---|
| `profiles` | `id` (=auth.users.id), `role` (`student` \| `contributor` \| `admin`), `created_at` | self-read; role writable by admin only |
| `instruments` | `id`, `name`, `slug`, `created_by` | read: any authed; write: contributor/admin |
| `manual_versions` | `id`, `instrument_id`, `title`, `edition`, `year`, `publisher`, `license_class` (`public_domain` \| `program_licensed`), `status` (`pending` \| `active` \| `archived`), `supersedes_id`, `source_object_path`, `page_count`, `created_by`, `published_by`, `published_at` | read: `status='active'` for any authed, plus own `pending` for its creator/admin; write: contributor/admin |
| `document_chunks` | `id`, `version_id`, `page`, `section`, `content`, `embedding vector(384)`, `table_ref`, `ocr_confidence` | read: only if the parent version is readable by the caller **and** `status='active'` (or caller is creator/admin, for review); write: service role only (ingestion) |
| `ingest_jobs` | `id`, `version_id`, `state` (`queued`\|`parsing`\|`review`\|`published`\|`rejected`\|`failed`), `ocr_quality`, `flags` (jsonb), `error`, timestamps | read: creator/admin; write: service role |
| `query_log` | `id`, `user_id`, `version_id`, `question`, `answer`, `abstained`, `citations` (jsonb), `retrieved` (jsonb: chunk ids + scores), `verify` (jsonb), `latency_ms`, `at` | insert: authed (own row); read: admin (+ own); no update/delete |
| `audit_log` | `id`, `actor_id`, `action`, `target`, `meta` (jsonb), `at` | read: admin (+ own); **no update/delete policy** (append-only) |

- HNSW index on `document_chunks.embedding` (`vector_cosine_ops`).
- `match_chunks(p_version_id uuid, p_query_embedding vector, p_k int)` — declared
  **`security invoker`** so RLS applies to the caller. This is the isolation boundary; nothing
  else queries `document_chunks` to answer a user question.

### Core types (`supabase/functions/_shared/schema.ts`, mirrored in `src/lib/schema.ts`)

```ts
type Citation     = { chunkId: string; page: number; quote: string };
type AnswerResult = {
  answer: string;
  citations: Citation[];
  abstained: boolean;                 // true => answer is the "not found in this version" message
  versionId: string;
  retrieved: { chunkId: string; page: number; score: number }[];
};
type VerifyResult = { supported: boolean; unsupportedClaims: string[] };
```

`llm.ts` requests JSON, then `JSON.parse` → extract first `{…}` → one retry with a
"valid JSON only" nudge → else return an abstention. Validate every result with `zod`. **No path
returns unvalidated model text.**

## Phase 0 — MVP notebook

`notebooks/mvp.ipynb`, one cell per step, top to bottom:

1. Load 2 real public-domain manuals (e.g. a PHQ-9/GAD-7 scoring guide + one IPIP scale manual).
2. Docling parse → structured text + tables.
3. Chunk (layout-aware; keep tables whole).
4. Embed with `thenlper/gte-small`; store vectors + `version_id` + page in a local pgvector table
   (or a Supabase dev project).
5. Retrieval filtered to one `version_id`, `k≈10–12`. No reranker.
6. Answer call (citation contract) + verify call, against whatever `LLM_BASE_URL` is configured.
7. Two demo queries: one answerable (expect a cited answer), one answerable only from the *other*
   manual (expect abstention).

**Checkpoint:** runs clean; one good cited answer and one correct "not found in this version". If
parsing mangles the norm tables or retrieval bleeds across versions, resolve before Phase 1.

### Phase 1 sub-step delivery (parallelised 2026-09-08)

Two lanes against the contract below. Lane A: `app-developer` main thread — 1c (upload) → 1d
(`ingest-dispatch`) → 1f (review/publish). Lane B: one subagent — 1e (`ingest/` + `ingest.yml`)
+ 1g (`keepwarm.yml`).

**Shared contract (build to this exactly):**

*Object path:* uploads go to the `manuals` bucket at
`v/<version_id>/source.pdf` (one object per version).

*`repository_dispatch` payload* — `ingest-dispatch` (1d) → `POST /repos/chiragsingla25/verbatim/dispatches`:
```json
{ "event_type": "ingest",
  "client_payload": { "job_id": "<uuid>", "version_id": "<uuid>", "object_path": "v/<version_id>/source.pdf" } }
```
`ingest.yml` (1e) triggers on `repository_dispatch` type `ingest` and calls
`python -m ingest.run --job-id <> --version-id <> --object-path <>`.

*`ingest_jobs.state` machine:*
`queued` (written by 1d on dispatch) → `parsing` (run.py at start) → `review` (run.py after
chunks inserted OK) → `published` | `rejected` (both by 1f) ; `failed` (run.py on any exception,
with `ingest_jobs.error` set). `ocr_quality` = mean chunk OCR confidence; `flags` = jsonb array
of strings (e.g. `["encrypted_pdf"]`, `["low_ocr"]`, `["no_tables_found"]`).

*run.py responsibilities:* download `object_path` from `manuals` (service key) → magic-bytes
`%PDF-` check, reject encrypted (→ `failed`, flag `encrypted_pdf`) → Docling parse → chunk
(**Phase 0 deviation #2 fix**: page = the chunk's first/dominant body item's `prov.page_no`,
never `min()` across merged items) → embed `thenlper/gte-small`, **cast float32** (deviation #3)
→ insert `document_chunks` (parent `manual_versions.status` stays `pending`) → set
`manual_versions.page_count` → `ingest_jobs` → `review`. Uses only `SUPABASE_URL` +
`SUPABASE_SERVICE_ROLE_KEY`. Chunk/embed logic promoted from `notebooks/mvp.ipynb`.

*keepwarm.yml:* `schedule` cron every 3 days + `workflow_dispatch`; `curl -fsS` a health check —
`GET ${SUPABASE_URL}/rest/v1/ -H "apikey: <anon>"` (PostgREST root, 200 when the project is
awake). Anon key via repo secret `SUPABASE_ANON_KEY`.

## Phase 2 — `/ask` pipeline + evals

- `supabase/functions/ask/` per the file list. Pipeline: embed (built-in `gte-small`) →
  `match_chunks` RPC with the caller's JWT → build prompt → `generate` → `verify` → insert
  `query_log` → return `AnswerResult`. `verify` drops unsupported claims; if nothing supported
  remains, `abstained: true`. No reranker.
- `evals/golden_dataset.jsonl` — ≥ 15 hand-written cases across 2–3 manuals, each
  `{ versionId, question, expectedPage?, expectedAnswerContains?, shouldAbstain }`.
- `evals/ragas_suite.py` — faithfulness / answer-relevancy / context-precision, `--fail-under`.
- `evals/cross_version_leak.py` — for each manual, ask a question whose answer exists only in a
  *different* manual/version; assert `abstained === true`. Any leak fails the run.
- `.github/workflows/ci.yml` — `pnpm test`, `python evals/run_evals.py` (wraps both suites with
  fail-under), `anthropics/claude-code-action` review.

**Checkpoint:** CI green; RAGAS above thresholds; `cross_version_leak.py` passes with zero leaks.

  RAGAS, ~6–8 LLM calls). The **full RAGAS suite** (`run_evals.py`, faithfulness /
  answer-relevancy / context-precision + full leak matrix) runs in a separate
  `evals-nightly.yml` — `schedule` + `workflow_dispatch` — so it stays within Groq free-tier
  limits. Both use `--fail-under`.
- **No automated Claude PR review in v1.** Drop the `anthropics/claude-code-action` step from
  `ci.yml`; review stays manual / via the release-qa skill. (Removes the `ANTHROPIC_API_KEY`
  secret need.)
- **Abstention rule — partial keep.** `verify` returns
  `{ supported, unsupportedClaims, revisedAnswer }` (schema gains `revisedAnswer`): the model
  re-emits the answer with unsupported claims removed, keeping only what a retrieved chunk
  backs. If nothing supported remains → `revisedAnswer` is exactly the abstention message and
  `abstained: true`. Citations are filtered to those still backing a kept claim. Stays at
  **2 LLM calls** (generate + verify); no third rewrite call.

### Phase 2 build notes / deviations (2026-09-08)

- **`VerifyResult` gained `revisedAnswer: string`** — required by the partial-keep abstention
  rule. `_shared/schema.ts` + `src/lib/schema.ts` both updated; both also export
  `ABSTAIN_MESSAGE`. The mirror test now compares from `export const citationSchema` onward
  (the import line differs: `npm:zod@^4.1.5` in the Edge Function, bare `zod` in the SPA — the
  deploy bundler ignores `supabase/functions/deno.json` import maps, same as the Phase 1
  `@supabase/supabase-js` finding).
- **Golden dataset keys on a `version` slug + `evals/manifest.json`**, not an inline
  `versionId` as the spec sketched. Survives a corpus rebuild — `manifest.json` records the
  three published `versionId`s and the runner resolves slug → id.
- **The eval suite calls the DEPLOYED `/ask`**, not a local reimplementation of the pipeline —
  it must score exactly what ships. It mints a dedicated student JWT via the GoTrue admin API
  (`chiragsingla25+eval@gmail.com`).
- **`/ask` latency is 7–90 s** under Groq free-tier rate-limit backoff (spec's 5–15 s is
  aspirational). Mitigation is the eval cadence: `ci.yml` per-PR runs only `run_evals.py
  --quick` (4 cross-version-leak + 5 abstention + 3 answerable smoke ≈ 20 `/ask` calls);
  `evals-nightly.yml` runs the full suite + RAGAS on a schedule.
- **RAGAS is faithfulness + `LLMContextPrecisionWithoutReference` only** — `answer_relevancy`
  needs an embeddings model and extra calls; dropped to stay inside rate limits. The
  abstention / expected-substring checks cover "did it answer the right thing".
- **Eval finding folded back into the pipeline:** the answer step would answer a *tangential*
  question when the exact fact was absent (asked "which PHQ items are reverse-scored" it
  replied about the 0–3 / 0–27 scoring). `ANSWER_SYSTEM` now says "answer ONLY the specific
  question asked … do NOT answer a nearby or related question — abstain instead." Re-run:
  zero leaks, 100% abstention accuracy on the quick set. Also exposed a weak leak probe
  (`phq-vs-pss-leak`), rewritten to ask for a PSS-only norm-table fact.
- **No `anthropics/claude-code-action` step in `ci.yml`** (clarify decision) — removes the
  `ANTHROPIC_API_KEY` secret need.
- **`ci.yml` unit job also runs `pnpm lint` + `pnpm build` + `pnpm test:functions`** (Deno) —
  the 18 function tests weren't gated by anything before. Needs `packageManager` in
  `package.json` + a matching `pnpm-lock.yaml` for `pnpm/action-setup@v4` + `--frozen-lockfile`.
- **Groq free tier is 200,000 tokens/day (~15–25 full answers) — exhausted on 2026-09-08 by dev
  + test volume.** The `/ask` generate+verify calls send the full retrieved context (~4–8k
  tokens each). Symptom was misleading: `_shared/llm.ts` retried the daily-limit 429 on Groq's
  long `retry-after`, sleeping the Edge worker until `WORKER_RESOURCE_LIMIT` / 150s kill.
  Diagnosis (throwaway `diag` function): auth + embed + `match_chunks` = 4.7s; `Supabase.ai`
  gte-small embed = 121 ms — the architecture is fine, it's purely the token budget.
  - **Fixed** the hang: `LlmQuotaError` (429 body matching per-day/TPD/RPD, or `retry-after`
    > 20s) fails fast; `/ask` returns **503** "temporarily out of capacity" instead of a silent
    "Not found in this version" or a dead worker; `run_evals.py` exits **2** ("skipped — LLM out
    of quota", distinct from 1) and CI treats exit 2 as a non-blocking `::warning::`.
  - **Not fixed — needs a decision:** the Phase 2 checkpoint (eval suite green in CI) cannot
    pass until either the Groq daily quota resets (00:00 UTC) or `LLM_*` points at a funded
    endpoint. The proposal anticipated this ("add a card or a fallback provider when it outgrows
    ~15–25 Q/day"). The `/ask` pipeline itself is deployed and was verified answering correctly
    (PSS/PHQ/AUDIT cited answers + cross-version abstention) before the quota ran out.

## Deviations from spec

*(app-developer appends during Build, release-qa during Verify — one bullet per divergence:
`[phase N / verify] <what diverged> — <why> — <how resolved>`. Leave a single "None" bullet if
nothing diverged.)*

- **[phase 0] Vector store for the MVP notebook is the real Supabase project, not a local
  pgvector.** — clarify-pass decision (2026-09-08): no Docker/`supabase` CLI on the machine, and
  `.env.local` already had project creds. — Notebook creates/drops a `mvp_chunks` scratch table
  over a direct `psycopg` connection (`SUPABASE_DB_URL`, session pooler); no HNSW, no RLS, no
  `match_chunks` RPC (all Phase 1/2). Direct-connection host is IPv6-only and didn't resolve
  locally → used the **session pooler** connection string.
- **[phase 0] Groq free-tier 429s on bursts.** — 4 answer/verify calls back-to-back exceed the
  free-tier rate limit. — Added request throttle + `Retry-After`/exponential backoff to the
  notebook's `_chat`. Carry into `supabase/functions/_shared/llm.ts` and the Phase-2 eval runner;
  CI eval throughput is capped by this (already flagged in CLAUDE.md as ~15–25 Q/day).
- **[phase 0] Chunk→page attribution is wrong for cross-page merged chunks.** — `HybridChunker`
  merged a page-6 text item with the page-7 PHQ-9 severity table; taking `min(pages)` attributed
  the chunk (hence a citation) to p6. Docling's own `table.prov.page_no` (7) is correct. — Phase-1
  ingestion must attribute a chunk to its dominant/first body item's page, or not merge across
  page boundaries. Page-citation accuracy is a core product property, so this is blocking for
  Phase 1, not cosmetic.
- **[phase 0] `gte-small` via `sentence-transformers` returns float16.** — default dtype on this
  box. pgvector stored it without complaint. — Phase-1 ingestion (`ingest/embed.py`) should cast
  to float32 before insert for determinism/headroom.
- **[phase 0] Docling misdetects the PSS page-2 questionnaire response grid as a table** and
  duplicates cells. — It's the item list, not a scoring/norm table; the clean text is also emitted
  as text items, and retrieval/answers were unaffected. — Left as-is for v1; note for Phase 1 in
  case contributor table-review needs a "not really a table" dismiss action.
- **[phase 1a] Role claim is `user_role`, not `role`.** — Spec says the access-token hook "puts
  `role` in the JWT". Supabase reserves the top-level `role` claim for the Postgres role
  PostgREST switches to; overwriting it breaks auth. — `custom_access_token_hook()` sets a
  `user_role` claim instead. RLS policies don't rely on the claim at all — they use
  `auth_role()` (security-definer read of `profiles`), which is recursion-safe and can't go
  stale. The claim is a convenience for the SPA / Edge Functions.
- **[phase 1a] Migrations applied via `supabase db push --db-url <session-pooler>`, not a linked
  project.** — `supabase link` needs an access token; the pooler URL + `--db-url` doesn't, and
  it's enough for `db push`. `supabase link` + `functions deploy` still need the token (1d).
- **[phase 1b] Supabase built-in email is ~2/hour and its validator rejects non-deliverable
  domains** (`.test`, `example.com`). — Makes real signup email impractical for iterative
  testing, and needs a live domain for test users. — 1b verified via
  `POST /auth/v1/admin/generate_link` (no send) — exercises the real verify → callback →
  `detectSessionInUrl` → session path, i.e. every line of SPA code; only Supabase's own mail
  delivery is unexercised. Real first signup (owner's actual email, once) will send one mail and
  work. If the pilot needs reliable signup email, wire custom SMTP (Resend/Postmark free tier) —
  record it then.
- **[phase 1b] Vite 8 + pnpm 12 gates package build scripts.** — `esbuild`'s postinstall is
  blocked until approved. — `pnpm-workspace.yaml` carries `onlyBuiltDependencies: [esbuild]`
  (pnpm 12 moved this out of `package.json`); CI must run `pnpm approve-builds --all --yes` or
  ship the same workspace file.
- **[phase 1d] `ingest-dispatch` runs `--no-verify-jwt` + a custom `x-webhook-secret` header.** —
  The caller is a Supabase Storage/DB webhook (pg_net), which sends no Supabase JWT; the spec
  only said "verifies `STORAGE_WEBHOOK_SECRET`" without a mechanism. — Header check
  `x-webhook-secret == STORAGE_WEBHOOK_SECRET`; the dashboard webhook must be configured to send
  that header. Handler split into `handler.ts` (pure, DI'd, 8 `deno test` cases) + `index.ts`
  (bootstrap) so tests need no node_modules.
- **[phase 1e] `SUPABASE_DB_URL` is a required THIRD Actions secret for `ingest.yml`.** —
  `ingest/run.py` writes `document_chunks` / `ingest_jobs` straight to Postgres via `psycopg` +
  the service role (both tables are service-role-only by RLS design; PostgREST bulk-insert of
  384-dim vectors is awkward). Storage download still uses the REST API + service key. —
  `.env.example` and both workflow headers list it.
- **[phase 1e] `ocr_confidence` is a layout/parse-quality proxy, not a true OCR score.** — Docling
  reports `ocr_score = nan` for digital (non-scanned) PDFs. — Per-chunk value = the page's
  Docling `ocr_score` if present else the page `mean_score` (same 0–1 range);
  `ingest_jobs.ocr_quality` = mean across chunks; `low_ocr` flag at `< 0.8`. Digital test PDFs
  score ~0.91. A genuinely scanned upload carries a real `ocr_score` and the path is unchanged.
- **[phase 1e] Phase-0 dev #2 fix, concretely:** table chunks take the first *table* item's
  `prov.page_no`; non-table chunks take the first provenance-carrying item's. Plain "first item"
  would have reproduced the page-6 bug for the PHQ-9 severity table (its merged chunk is led by a
  page-6 paragraph). Reconfirmed: that chunk now attributes to page 7.
- **[phase 1e] `table_ref` = Docling `self_ref` (e.g. `#/tables/0`), so one misdetected "table"
  can map to many chunks with the same ref.** — The PSS p2 questionnaire grid (Phase-0 dev #5)
  splits into ~11 chunks all carrying `table_ref = "#/tables/1"`. — Fine for v1 (spec needs ≥1
  table chunk); the 1f review UI could add a "not really a table" dismiss later.
- **[phase 1e] CI torch install risk + cold-run model downloads.** — `ingest/requirements.txt`
  pins `torch==2.14.0` via `--extra-index-url .../whl/cpu` (Linux CPU wheel availability not
  verifiable offline — CI fails loudly if absent). First CI run also downloads Docling
  layout/OCR models + `thenlper/gte-small` weights at runtime (not pip-cached) → `ingest.yml`
  `timeout-minutes: 25`. The `not_a_pdf` failure branch is implemented but only the
  `encrypted_pdf` branch was exercised against the live DB.
- **[phase 1e] Partial ingest failure can orphan `document_chunks`.** — `run.py` runs
  `autocommit=True`; an exception after `insert_chunks` but before `job -> review` leaves chunks
  under a still-`pending` version (job goes `failed`). — Harmless (RLS hides non-active chunks;
  `match_chunks` needs an active parent), but a re-ingest should clear prior chunks for the
  version first. Deferred.
- **[phase 1f] `publish_manual_version` / `reject_manual_version` are `SECURITY DEFINER`, not
  invoker.** — They must also transition the `ingest_jobs` row (`published` / `rejected`), and
  `ingest_jobs` has no write policy (service-role only), so a security-invoker function called by
  a contributor silently no-ops that UPDATE. — Redefined as `security definer` with explicit
  in-function checks (authenticated, version exists, caller is `created_by` or admin, version is
  `pending`, latest job is `review` for publish), `search_path` pinned. `request_manual_upload`
  (1c) stays `security invoker` — it only writes tables a contributor already has INSERT rights
  on.
- **[phase 1f] Inline source-page images in the review UI deferred to Phase 3.** — Rendering PDF
  pages client-side (pdf.js) is the same work as the Phase 3 citation slide-over; doing it twice
  is waste. — 1f shows each extracted-table chunk with a link to `…/source.pdf#page=N` (signed
  URL). Phase 3 builds the real page viewer once.
- **[phase 1 wiring] Edge Function deploy ignores the `deno.json` import map.** — The Supabase
  remote bundler couldn't resolve the bare `@supabase/supabase-js` specifier from
  `supabase/functions/deno.json`. — `index.ts` uses an inline `jsr:@supabase/supabase-js@2`
  specifier (Supabase's own template convention); `deno.json` keeps the `no-import-prefix` lint
  exclusion and the `@std/assert` map for `pnpm test:functions`. Deployed with `--no-verify-jwt`.
- **[phase 1 wiring] Storage webhook is a `pg_net` trigger migration, not a dashboard Database
  Webhook.** — Keeps it in version control. `pg_net` wasn't enabled (migration does it);
  `public.notify_ingest_dispatch()` (not `storage.*` — `db push` gets "permission denied for
  schema storage" creating functions there) + an `after insert` trigger on `storage.objects`;
  `x-webhook-secret` read from Supabase **Vault** (`storage_webhook_secret`, created out of band
  via `vault.create_secret`, never committed). Function URL is hardcoded (project-specific, not
  secret).
- **[phase 1 wiring] `keepwarm.yml` had two bugs only CI surfaced.** (1) unquoted `run:` scalar
  containing `apikey: ` (colon-space) → YAML parse error, GitHub rejected the whole file (0s
  "failure"); fixed with a `|` block scalar. (2) PostgREST `/rest/v1/` returns **401** with only
  `apikey` — needs `Authorization: Bearer <anon>` too; now hits
  `/rest/v1/instruments?select=id&limit=1` with both headers (also touches Postgres, which is
  what the 7-day pause is about). — Local YAML-lint every workflow before pushing.
- **[phase 1 wiring] Actions secret `SUPABASE_ANON_KEY` was set from `.env.local`'s
  `VITE_SUPABASE_ANON_KEY`** (there is no bare `SUPABASE_ANON_KEY` in `.env.local`).
- **[phase 1 checkpoint] CI Docling ≠ local Docling.** The same `pss.pdf` yielded 8 chunks /
  1 `table_ref` / `ocr_quality` 0.86 on the Linux CI runner vs 16 / 12 / 0.91 on macOS —
  Docling + torch build differences. Ingestion invariants held (norm table captured as a table
  chunk, `job → review`, version stays `pending`). Flag for Phase 2: eval fixtures must be
  generated on (or pinned to) the CI environment, not local, or the golden set will drift.

### Verify pass (release-qa, 2026-09-08) — findings

- **[verify / phase 1a] `instruments` RLS was `FOR ALL` to any contributor with no ownership
  scope → cross-user corpus deletion.** Any contributor could `DELETE FROM instruments`; FK
  cascades (`manual_versions` → `document_chunks`) then wiped *another* contributor's published
  manuals. Confirmed live (contributor B deleted contributor A's instrument + version + chunk,
  HTTP 204). Same shape on `storage.objects` for the `manuals` bucket. — **Fixed**
  (`20260908160000`): `request_manual_upload` → `SECURITY DEFINER` with explicit in-function
  authz, so contributors need no write access to `instruments`; `instruments` write policy →
  admin only; `manuals` storage → contributor `INSERT` + `SELECT` only (signed URLs need it),
  no client `UPDATE`/`DELETE`. Re-verified live: B can't delete or rename A's instrument or
  delete A's PDF; admin still can.
- **[verify / phase 1a] `audit_log` accepted arbitrary client inserts.** `audit_log_insert_self`
  let *any* authenticated user (a plain student included) insert rows with any `action` /
  `target` / `meta` as long as `actor_id = auth.uid()`. Confirmed live (student inserted a
  fabricated `action='publish'` row, HTTP 201). — **Fixed** (`20260908160000`): dropped
  `audit_log_insert_self`; audit rows now originate only from the `SECURITY DEFINER` RPCs
  (`request_manual_upload` / `publish` / `reject`). Re-verified live: no client can insert;
  the RPCs still write `upload` / `publish` rows.
- **[verify / phase 1e] Re-ingestion was not idempotent.** `run.py` appended a second set of
  `document_chunks` on a re-dispatch for a still-`pending` version. — **Fixed** (`ingest/run.py`):
  `delete from document_chunks where version_id = %s` before insert. Re-verified: two
  back-to-back local `ingest.run` invocations → chunk count stable (16 == 16).
- **[verify] Version-isolation boundary verified correct.** The spec's load-bearing property
  holds: a non-owner (student) gets 0 rows from a pending version's `document_chunks` via a
  direct select *and* via `match_chunks()` (`security invoker`); `publish`/`reject` definer
  functions are correctly ownership-gated (creator or admin only, no escalation path to `role`);
  `profiles.role` is admin-write-only (no self-promotion). No cross-version leak found.
- **[verify] Out of the reviewed diff: the project carries an `ensure_rls` event trigger
  (`public.rls_auto_enable`, `SECURITY DEFINER`) that auto-enables RLS on new `public` tables.**
  Pre-existing (project created 2026-09-07), not in `supabase/migrations/`, additive-safety
  only. Noted for awareness — it is not version-controlled.
- **[verify] CI must run both `pnpm test` and `pnpm test:functions`.** The 8 Deno tests for
  `ingest-dispatch` are not run by `pnpm test` (vitest is scoped to `src/`); Phase 2's `ci.yml`
  needs an explicit Deno step or they gate nothing.
- **[verify] Independent sweep green:** `pnpm test` (3), `pnpm test:functions` (8),
  `pnpm build`, `pnpm lint` (1 benign fast-refresh warning). All 7 spec tables + columns match;
  enums-as-CHECK, HNSW cosine index, `match_chunks` security-invoker, `user_role` claim all as
  recorded. No scratch tables left in the project.
