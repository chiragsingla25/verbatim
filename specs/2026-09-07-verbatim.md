# Spec — Verbatim v1

Build contract for app-developer. Decisions and rationale are in `docs/proposal.md`; this file is
what "done" is measured against. Phases are hard gates — implement one, report what you verified,
stop for approval.

---

## Prior art & scope rationale

Comparable products and what this build takes / leaves (full table in `docs/proposal.md`):

- **NotebookLM** — take: inline per-claim citations that open the source; "answers only from
  sources" stance. Leave: audio overviews, collab.
- **Humata / PDF.ai** — take: page-level citations, a multi-doc library. Leave: team seats, export
  formats.
- **Mintlify / GitBook / ReadMe "Ask AI"** — take: a version switcher that scopes both search and
  chat (→ the locked version selector). Leave: docs authoring.
- **Harvey / CoCounsel** — take: answer-to-source traceability, explicit abstention, "verify
  against source" framing. Leave: the N-questions × M-docs table (deferred batch-Q&A).
- **Pearson Q-global / PAR PARiConnect** — not Q&A tools; "qualified user" gating not needed for a
  public-domain corpus with no client data.

**Novelty:** no product does version-scoped Q&A over psychological test manuals → the
`cross-version-leak` eval is a required, blocking check.

## Out of scope for v1

Planner–orchestrator / adaptive routing · edition-comparison ("what changed") · score / CI / RCI
calculators · quizzes / flashcards / study tracking · course workspaces & shared annotations · APA
citation generator & answer export · SSO / MFA / step-up auth · PDF sanitisation & malware scan ·
two-person review · restricted-manual tier & per-manual access grants · instrument catalogue /
test-selection assistant · batch Q&A · any client-score entry · commercial/licensed manuals (v1
corpus is **public-domain instruments only**).

## System shape

- **Next.js (App Router) on Vercel** — UI + API routes.
- **Supabase** — Postgres + pgvector + Auth + RLS + Storage.
- **Modal** (Python) — serverless ingestion job, triggered by a Supabase Storage webhook.
- **Hosted APIs** — Gemini embeddings + answer/verify LLM (Gemini or Groq); Cohere/Jina rerank.

### Data model (Supabase)

| Table | Key columns | RLS |
|---|---|---|
| `profiles` | `id` (=auth.users.id), `role` (`student` \| `contributor` \| `admin`), `created_at` | self-read; admin-write role |
| `instruments` | `id`, `name`, `slug`, `created_by` | read: any authed; write: contributor/admin |
| `manual_versions` | `id`, `instrument_id`, `title`, `edition`, `year`, `publisher`, `license_class` (`public_domain` \| `program_licensed`), `status` (`pending` \| `active` \| `archived`), `supersedes_id`, `source_object_path`, `page_count`, `created_by`, `published_by`, `published_at` | read: `status='active'` for any authed, plus own `pending` for its creator/admin; write: contributor/admin |
| `document_chunks` | `id`, `version_id`, `page`, `section`, `content`, `embedding` (vector), `table_ref`, `ocr_confidence` | read: only if parent version readable by caller **and** `status='active'` (or caller is creator/admin for review); write: service role only (ingestion) |
| `ingest_jobs` | `id`, `version_id`, `state` (`queued`\|`parsing`\|`review`\|`published`\|`rejected`\|`failed`), `ocr_quality`, `flags` (jsonb), `error`, timestamps | read: creator/admin; write: service role |
| `audit_log` | `id`, `actor_id`, `action`, `target`, `meta` (jsonb), `at` | read: admin (+ own rows); **no update/delete policy** (append-only) |

- `document_chunks.embedding` dimension = `EMBEDDING_DIM`. An IVFFlat/HNSW index on it.
- Retrieval is a Postgres function `match_chunks(p_version_id uuid, p_query_embedding vector, p_k int)`
  declared **`security invoker`** so RLS applies to the caller — this is the isolation boundary.


### Core types (`src/lib/answer/schema.ts`)

```ts
type Citation   = { chunkId: string; page: number; quote: string };
type AnswerResult = {
  answer: string;
  citations: Citation[];
  abstained: boolean;              // true => answer is the "not found in this version" message
  versionId: string;
  retrieved: { chunkId: string; page: number; score: number }[];  // evidence trace
};
type VerifyResult = { supported: boolean; unsupportedClaims: string[] };
```

`generate.ts` and `verify.ts` request structured output matching these — no free-text parsing.

## Phase 0 — MVP notebook

`notebooks/mvp.ipynb`, one cell per step, top-to-bottom:

1. Load 2 real public-domain manuals (e.g. a PHQ-9/GAD-7 scoring guide + one IPIP scale manual).
2. Docling parse → structured text + tables.
3. Chunk (layout-aware; keep tables whole).
4. Gemini embed; store vectors + `version_id` + page in a local pgvector table (or Supabase dev).
5. Retrieval filtered to one `version_id`; rerank the top-k.
6. Answer call with the citation contract; verify call.
7. Two demo queries: one answerable (expect a cited answer), one answerable only from the *other*
   manual (expect abstention).

**Checkpoint:** notebook runs clean; shows one good cited answer and one correct "not found in this
version". If parsing mangles the norm tables or retrieval bleeds across versions, that's a Phase-0
finding — resolve before Phase 1.

## Phase 1 — Data model, auth, ingestion

- `supabase/migrations/` — all tables above, RLS policies, `match_chunks`, and the auth
  access-token hook that puts `role` into the JWT.
- Self-serve sign-up (`/sign-up`) + mandatory email verification; new `profiles` row defaults to
  `role='student'`.
- `api/uploads/init` — contributor submits metadata + rights attestation → creates a `pending`
  `manual_versions` row + returns a short-TTL signed upload URL scoped to one object path.
- `api/webhooks/storage` — verifies `STORAGE_WEBHOOK_SECRET`, enqueues an `ingest_jobs` row,
  triggers the Modal job.
- Modal `src/ingest/app.py` — magic-bytes PDF check, reject encrypted; Docling parse; chunk; embed;
  insert `document_chunks` (parent version stays `pending`); write `ocr_quality` + `flags` to
  `ingest_jobs`.
- `/upload/[versionId]/review` — extracted tables beside source page images; contributor confirms;
  `api/uploads/[versionId]/publish` flips `status='active'` and writes an `audit_log` row.

**Checkpoint:** a contributor uploads a real public-domain PDF, reviews the tables, publishes; a
newly signed-up student sees the manual in `/library`; a direct `select` on a `pending` version's
chunks (as the student) returns nothing (RLS). `audit_log` has the upload + publish entries.

## Phase 2 — Answer pipeline + evals

- `src/lib/answer/*` per the file list; `pipeline.ts` = retrieve → rerank → generate → verify,
  returning `AnswerResult`. `verify.ts` drops unsupported claims; if nothing is left supported, the
  result is `abstained: true`.
- `api/ask/route.ts` — auth required; calls `pipeline` with the caller's Supabase client so
  `match_chunks` runs under their RLS.
- `evals/golden_dataset.jsonl` — ≥ 15 hand-written cases across 2–3 manuals, each
  `{ versionId, question, expectedPage?, expectedAnswerContains?, shouldAbstain }`.
- `evals/ragas_suite.py` — faithfulness / answer-relevancy / context-precision, `--fail-under`.
- `evals/cross_version_leak.py` — for each manual, ask a question whose answer exists only in a
  *different* manual/version; assert `abstained === true`. Any leak fails the run.
- `.github/workflows/ci.yml` — `pnpm test`, `python evals/run_evals.py` (wraps both suites with
  fail-under), `anthropics/claude-code-action` review.

**Checkpoint:** CI green; RAGAS above thresholds; `cross_version_leak.py` passes with zero leaks.

## Phase 3 — UI (Direction B) + ship

- `/sign-in`, `/sign-up`, `/library`, `/upload/[versionId]/review`, `/ask`.
- `/ask` — reading-first: one centered column; a **locked version selector** pinned at the top of
  every answer; inline citation chips; the amber "Not found in this version" state with a
  "switch version" affordance; clicking a citation opens a **slide-over** with the source page and
  the quoted passage highlighted. Match the Verbatim UI canvas.
- Deploy: Vercel (app) + Supabase (prod project) + `modal deploy` (job). CI gate enforced on `main`.
- Decide: does Langfuse tracing (`LANGFUSE_*`) land now, before real students, or immediately
  after? Record the call here.

**Checkpoint:** on the deployed URL, a student signs up → verifies email → asks a question → gets a
cited answer and can open the source; a contributor uploads → reviews → publishes a manual. Both
paths complete without manual DB intervention.

---

## Verification step (whole build)

The build is done when, on the deployed app:
1. the Phase 3 checkpoint passes end to end, and
2. `python evals/run_evals.py` passes (RAGAS thresholds + zero cross-version leaks + abstention
   accuracy), and
3. a fresh-context review of the full diff against this spec finds no correctness gap.
