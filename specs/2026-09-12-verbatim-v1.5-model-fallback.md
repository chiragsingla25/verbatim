# Verbatim v1.5 — model fallback + selector

## Prior context

OpenRouter's free model (`inclusionai/ling-3.0-flash-sante:free`) is capped at 1,000 req/day
account-wide (documented in CLAUDE.md's "Before spending LLM quota" section, added this
session after repeatedly hitting it). When the cap is hit, every `/ask` call currently returns
a hard "answer service is busy" — there is no fallback. The user has OpenRouter credit already
loaded and wants: stay on the free model by default, fall back to a paid model
(**Qwen3.7 Flash**, `qwen/qwen3.7-flash` — same OpenRouter account/key, only `LLM_MODEL`
differs, ~$0.03/$0.13 per 1M tokens under 32K input) when the free model is unavailable, and a
small UI control to see and choose which model answers — built as a small **registry**, not a
one-off free/paid special case, so a third model is a one-line addition later.

### Intake decisions (2026-09-12)

- **Fallback trigger:** any non-2xx response or a request timeout from the active model — not
  narrowed to 429 only. `llmChat` gets an explicit per-request timeout (via `AbortController`;
  none exists today) so a hang becomes a catchable failure instead of tying up the ~150s Edge
  Function wall clock.
- **Fallback scope:** **whole-turn**. The first failure on any of a turn's LLM calls
  (condense / answer / verify) advances a shared, turn-scoped "active model" index; every
  remaining call in that turn uses the new active model directly, no re-trying the one that
  just failed. One model answers one turn — `AnswerResult.modelId` is unambiguous.
- **UI:** not a passive per-answer badge. A **model selector in the Ask composer** (a small
  `<select>`, not a dashboard), defaulting to "Free". Picking "Qwen 3.7 Flash" explicitly
  starts that turn's chain at Qwen (skips the free model entirely — a deliberate choice).
  Leaving it on "Free" and having the free model fail **auto-advances the selector itself**
  to show "Qwen 3.7 Flash" after that turn, so the control doubles as both the preference-
  setter and the current-status indicator — the user can always flip it back to "Free" to
  retry. Registry-driven: the dropdown renders from the same small model list the server
  validates against, so adding a model later is a one-line addition to that list, not new
  branching logic in the component.
- **Cost guardrail:** none for now. At this app's volume even an extended free-model outage
  falling back on every call costs cents; the selector's visibility is the guardrail. No
  cap/circuit-breaker, no new tracking table.
- **Recording:** `AnswerResult` gains `modelId: string` (whichever model actually answered —
  always populated, including `abstained` and `meta` kinds, since even a meta/condense-only
  turn goes through the same fallback-chat wrapper). `query_log` gains a matching column.

## Scope

1. **Model registry** (`_shared/schema.ts` + `src/lib/schema.ts` mirror, kept identical per
   `.claude/rules/src.md`): an ordered list of `{ id, label, llmModel, free }`, seeded with
   `free` (the current OpenRouter free model) and `qwen` (Qwen3.7 Flash), plus a
   `DEFAULT_MODEL_ID = 'free'`. The client mirror includes the raw `llmModel` slug too (not a
   secret — only the API key is) so both copies stay byte-identical, matching the project's
   existing mirror convention rather than introducing a partial-mirror exception.
2. **`_shared/llm.ts`**: `llmChat` takes an explicit `model: string` parameter instead of
   reading `LLM_MODEL` from env (still reads `LLM_BASE_URL`/`LLM_API_KEY` from env — those
   stay constant across models, same account). Add a request timeout (`AbortController`,
   ~30s) so a hang throws instead of hanging. New `createChatWithFallback(models, startId)`
   returns `{ chat: ChatFn; getModelUsed: () => string }`: `chat` tries the active model,
   and on ANY thrown error advances through the remaining models in registry order, sticking
   with whichever one succeeds for the rest of the closure's lifetime (one instance built per
   `ask()` call = one instance per turn, giving the whole-turn stickiness above for free).
3. **`pipeline.ts`**: `AskInput` gains `modelId?: string`. `AnswerResult` (schema) gains
   `modelId: string`, populated from `deps.chat`'s paired `getModelUsed()` at every return
   point (`abstain`, `meta`, `grounded`).
4. **`index.ts`**: validate the incoming `modelId` against the registry (unknown/missing →
   `DEFAULT_MODEL_ID`); build one `createChatWithFallback(MODEL_REGISTRY, resolvedId)` per
   request; wire its `.chat` into `AskDeps.chat`; write `model_used` into the `query_log` row.
5. **Migration**: `query_log` gets `model_used text not null default 'free'`. No RLS change —
   same row, same policies.
6. **SPA**: `src/lib/api.ts`'s `ask()` gains an optional `modelId` param (sent in the POST
   body, defaults to `DEFAULT_MODEL_ID` when omitted). `src/routes/Ask.tsx` composer gets a
   small `<select>` next to the input, rendered from `MODEL_REGISTRY`, defaulting to "Free";
   after each answer, the selector updates to `result.modelId` so an auto-fallback is visible
   and persists (as the new preference) until the user manually changes it back.

## Out of scope

- A cost/usage dashboard, admin visibility into fallback frequency, or a spend cap — deferred,
  see the cost-guardrail intake decision above.
- Any change to retrieval, the answer/verify prompts themselves, or the three response kinds.
- A third model — the registry makes adding one trivial later, but only `free` + `qwen` ship
  now.
- Per-call (rather than per-turn) model selection — a follow-up's condense/verify calls always
  match whichever model answered that turn's first call.
- Streaming, or any change to `AnswerCard.tsx`'s per-message rendering — the model signal lives
  in the composer selector, not on each answer bubble.

## Architecture change

Additive to the existing pipeline: same three response kinds, same retriever, same
`AskDeps`-shaped dependency injection. The only structural change is `AskDeps.chat` now comes
from a small stateful wrapper instead of the bare `llmChat` function — `pipeline.ts`'s own
logic (condense → embed → match → answer → verify) is untouched.

## Phase 1 — Registry + server-side fallback chain

**Files**
- `supabase/functions/_shared/schema.ts` + `src/lib/schema.ts` — `ModelOption` type,
  `MODEL_REGISTRY: ModelOption[]`, `DEFAULT_MODEL_ID`.
- `supabase/functions/_shared/llm.ts` — `llmChat(model, system, user)` (parameterized,
  + request timeout); `createChatWithFallback(models, startId)`.
- `supabase/functions/ask/pipeline.ts` — `AskInput.modelId?`; `AnswerResult.modelId` wired
  through every return path.
- `supabase/functions/ask/index.ts` — validate `modelId`, build the fallback chat, log
  `model_used`.
- `supabase/migrations/20260912NNNNNN_query_log_model.sql` (new) — the column.
- Deno tests (`pipeline.test.ts`, `llm.test.ts` if one doesn't exist): fallback fires on a
  thrown error from the first model and not before; the chain sticks with the model that
  succeeded across multiple `.chat()` calls in the same instance (simulating condense+answer+
  verify); an unknown/missing `modelId` resolves to `DEFAULT_MODEL_ID`; `getModelUsed()`
  matches what a `meta`-kind (condense-only) turn actually used.

**Checkpoint:** a fake `ChatFn` chain (first model throws, second succeeds) drives `ask()` to
a grounded result whose `modelId` is the second model's id, exercised via `pnpm test:functions`
— no live OpenRouter call needed for this phase. `deno check` clean.

## Phase 2 — SPA selector

**Files**
- `src/lib/api.ts` — `ask()` gains `modelId?: string` (sent in the request body).
- `src/routes/Ask.tsx` — small `<select>` in the composer row, options from
  `MODEL_REGISTRY`, defaults to `DEFAULT_MODEL_ID`; on each answer, `setModelId(result.modelId)`
  so a server-side fallback is reflected back into the control.

**Checkpoint (browser + one real `/ask` call — the one LLM-calling step in this build,
flagged to the user beforehand per CLAUDE.md's "Before spending LLM quota" with its call-count
estimate):** the selector shows "Free" by default; asking a question with the free model
available answers normally and the selector stays on "Free"; forcing a failure (e.g.
temporarily pointing `LLM_MODEL`'s registry entry at an invalid model string, or asking while
quota is genuinely exhausted) causes the answer to still come back grounded, sourced from Qwen,
and the selector visibly flips to "Qwen 3.7 Flash". Manually selecting "Qwen 3.7 Flash" up
front skips the free model entirely for that turn.

## Deviations from spec

### Phase 1 (build)

- **`AskInput` did NOT gain `modelId?: string`** as originally specified. Tracing the actual
  data flow: `pipeline.ts` never needs the *requested* model — only the *actually-used* one,
  which it already gets via `deps.getModelUsed()` (correct even after a mid-turn fallback,
  where the requested and used model differ). Adding an unread field to `AskInput` would be
  dead weight a reviewer would flag. Model resolution lives entirely in `index.ts` (validate
  the raw request → build one `createChatWithFallback` → pass its `.chat`/`.getModelUsed`
  through `AskDeps`), which is where the spec's own description of the flow already pointed.
- **`createChatWithFallback` gained an injectable `callModel` parameter** (defaults to
  `llmChat`) beyond the spec's stated signature. Without it, the fallback/stickiness/chain-
  exhaustion logic could only be tested against a real network call — this repo's whole
  testing philosophy (`AskDeps` dependency injection, no network in `deno test`) argues
  against that, so the wrapper got the same treatment `pipeline.ts` already has.
- Fallback tests live in a new `supabase/functions/_shared/llm.test.ts` (the spec allowed
  either location); `pipeline.test.ts` covers the pipeline's own consumption of
  `getModelUsed()` (grounded / abstained / meta all report it correctly), not the fallback
  logic itself.
- `src/lib/schema.test.ts`'s "well-formed AnswerResult" fixture needed `modelId` added —
  caught immediately by the existing test suite, not a surprise, just noting the mirror's
  test coverage did its job.
