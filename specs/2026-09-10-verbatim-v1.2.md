# Spec addendum — Verbatim v1.2: conversational memory + session-grouped history

Build contract for app-developer, extending v1 / v1.1 / v1.1.1 / v1.1.2 (all frozen build
records). Same stack and deployment — Vite + React SPA on GitHub Pages, Supabase Postgres +
pgvector + Auth + Storage + Edge Functions.

**This is a deliberate evolution of the core `/ask` design**, not a bolt-on. `/ask` stops
being single-turn: it now answers a follow-up with the conversation so far as context, and
"My answers" becomes a list of conversations you can re-open and continue. The change to the
grounding contract is spelled out in *Architecture change* below and must be mirrored into
`CLAUDE.md` in Phase 2.

Delivery model: single generalist developer + a fresh-context `/code-review` at each phase
boundary. Phase 2 touches the LLM pipeline and the "cited or abstained" invariant — the most
quality-sensitive change in the project's history — so the eval suite is the release gate.

Built as **one addendum, one ship** (user decision): three sequential build increments, each
with its own checkpoint + `/code-review`, then a single whole-addendum release-qa Verify +
Ship. Not shipped phase-by-phase.

---

## Scope

1. **Conversational `/ask`** — a follow-up in the same session is answered using the prior
   turns. Pronoun/topic resolution ("the cutoff for it"), scoped follow-ups ("explain more",
   "what about the GAD-7 section"), and questions about the conversation itself ("what did I
   just ask", "summarise what we've covered").
2. **Sessions** — `query_log` gains a `session_id` + `turn`; every `/ask` is tagged. The Ask
   thread is persisted (survives reload) and version-locked to one manual version.
3. **"My answers" → conversations** — the flat per-answer list (v1.1) becomes a list of
   conversations, each re-openable and continuable.

**Out of scope for v1.2** (stay deferred): a planner / ReAct loop / tool-use agent (this is a
*fixed* conversational pipeline, not an agent); edition comparison; batch Q&A; reranker;
citation export; cross-session memory ("remember what I asked last week"); sharing a
conversation with another user; renaming / foldering conversations; per-PR full-RAGAS gating.

## Intake decisions (2026-09-10)

- **Memory mechanism:** the answer LLM receives the **conversation history plus the retrieved
  chunks** — ChatGPT / Claude-style. Not the safer condense-only rewrite. The user accepted
  the pre-mortem: the grounding guarantee is preserved by a **history-aware `verify`** (below),
  which is a hard requirement, not a nice-to-have.
- **History window:** a **recent token-budget window** (as many recent turns verbatim as fit
  under a budget that leaves room for the 12 chunks + prompts + answer) **plus a rolling
  LLM-written summary of everything older**, so a long conversation still "remembers" its
  start. The summary is **context for understanding the question only — never a source of a
  claim** (a grounded answer's claims are still `verify`-gated against *this turn's* chunks; a
  bad summary can at worst misdirect retrieval → an abstain or a less-relevant grounded
  answer, never a wrong fact). Summarisation runs only when a turn ages out of the recent
  window (short chats never pay for it).
- **Phasing:** everything ships together (one release-qa, one deploy), built in three
  checkpointed increments.
- **Resume:** yes, from day one — a past conversation re-opens in Ask with its transcript and
  continues under the same `session_id`.
- **Meta questions:** answered from the transcript — a third response kind alongside
  "grounded" and "abstained".

## Architecture change (mirror into CLAUDE.md in Phase 2)

- `/ask` is **conversational RAG, still a single retriever, still not an agent.** Retrieval is
  unchanged: one `match_chunks` call, RLS-enforced, filtered to the one locked `version_id`.
  What's new is that the **answer step** also receives the last *N* turns of the conversation
  (bounded — see Phase 2), and a cheap **condense** step rewrites a follow-up into a
  standalone query *for the embedding/retrieval step only*.
- **Three response kinds, not two.** `CLAUDE.md`'s "no third state" becomes:
  1. **grounded** — ≥ 1 citation to a chunk in the requested `version_id`;
  2. **abstained** — `abstained: true`, no citation, "not found in this version";
  3. **meta** — a question about the conversation itself, answered from the transcript, with
     **no citation and no manual claim** (`kind: 'meta'`). Never used to state a fact about an
     instrument.
- **The grounding guarantee is unchanged for kinds 1–2 and enforced by a history-aware
  verify:** every factual claim in a grounded answer must trace to a chunk **retrieved on
  this turn** — not to the transcript, not to the rolling summary, not to a chunk retrieved
  on an earlier turn. A claim whose only support is the conversation history/summary is
  dropped; if that empties the answer, the turn abstains. The manual is the only source of
  instrument facts; history + summary are only context for *what is being asked*. Never the
  open web.
- **Rolling summary.** Turns that fall out of the recent token-budget window are folded, once,
  into a persisted per-session `summary` by a dedicated LLM call. The summary + the recent
  verbatim turns together always cover the whole conversation with no gap. The summary is
  passed to the condense step and the answer step as context; it is **never** passed to
  verify and never produces a citation.
- **A single-turn call is a conversation of length 1.** `/ask` with an empty history behaves
  exactly as v1.1.2 does today — the existing abstention and cross-version-leak evals must
  stay green unchanged.

## Prior art & scope rationale

The conversation model is the one every LLM chat product uses: a left-hand list of past
conversations, each re-openable, new turns appended, the model sees the transcript. The RAG
half is standard "conversational retrieval" — a condense/standalone-question step feeding an
unchanged retriever, with the transcript also visible to the generator. Verbatim's twist,
and the only genuinely load-bearing design work here, is keeping the **verify** step as a
hard grounding backstop once the generator can see prior answers — so a follow-up can never
inherit an unverified number from three turns ago. **Deliberately not copied** from ChatGPT
et al.: automatic conversation titles via an LLM call (use the first question), semantic
search over past conversations, cross-conversation memory, and message editing/branching —
all overkill for an internal pilot. No formal library evaluation: the pipeline is hand-rolled
(no LangChain, per `CLAUDE.md`) and the risk lives entirely in the eval gate, not in a
framework choice.

## Phased build plan

### Phase 1 — session data model + persisted thread (no pipeline behaviour change)

**Files**
- `supabase/migrations/20260911100000_chat_sessions.sql` **(new)**:
  - **`chat_sessions` table** (a real table, not a view — it holds the rolling summary):
    `id uuid pk default gen_random_uuid()`, `user_id uuid not null references auth.users`,
    `version_id uuid not null references manual_versions`, `title text` (the first question,
    truncated), `summary text not null default ''`, `summary_through_turn int not null
    default 0`, `started_at timestamptz not null default now()`, `last_at timestamptz not
    null default now()`, `turn_count int not null default 0`.
    RLS: `select` self-or-admin (mirror `query_log_select_self_or_admin`); `insert` +
    `update` where `user_id = auth.uid()` (so `/ask`, running under the caller's JWT, can
    create the row on turn 1 and bump `last_at` / `turn_count` / `summary` each turn); **no
    delete policy** (eval-corpus integrity, same as `query_log`).
  - `alter table public.query_log add column session_id uuid`, `add column turn int`.
  - Backfill: for each existing `query_log` row, create a matching `chat_sessions` row
    (`id = query_log.id`, `title` = its question, `turn_count = 1`, timestamps from `at`)
    and set `query_log.session_id = query_log.id`, `turn = 1`. (Each historical row = a
    complete 1-turn session.)
  - `alter query_log.session_id set not null`, add
    `references public.chat_sessions (id)`; `turn` `not null default 1 check (turn >= 1)`.
  - Index `query_log_session_idx on (session_id, turn)`; `chat_sessions` index on
    `(user_id, last_at desc)`; keep the existing `query_log` `user_id` / `at` indexes.
- `supabase/functions/ask/index.ts` — accept `sessionId` in the body (required; `UUID_RE`);
  reject if absent/invalid with 400. Pass through to the pipeline.
- `supabase/functions/ask/pipeline.ts` — `AskInput` gains `sessionId`. On each call:
  upsert `chat_sessions` (create on turn 1 with `title`/`version_id`; else bump `last_at`,
  `turn_count`); compute `turn = chat_sessions.turn_count` (post-bump) or
  `coalesce(max(query_log.turn),0)+1`; write `session_id` + `turn` on the `query_log` insert.
  **No history fetch, no prompt change, no verify change, no summary yet this phase.**
- `src/lib/api.ts` — `ask(versionId, question, sessionId)`; `getSession(sessionId)` →
  ordered `HistoryEntry[]` (reuse `toHistoryEntry`); `newSessionId()` = `crypto.randomUUID()`.
- `src/routes/Ask.tsx` — on mount, derive the session id from `?s=` in the URL; if absent,
  `newSessionId()` and `replace`-navigate to `/ask/:versionId?s=:sessionId`. If `?s=` is
  present, `getSession()` to rehydrate `turns`. `submit` sends `sessionId`. "New chat"
  control → fresh `?s=`.
- `src/lib/schema.ts` + `_shared/schema.ts` — `AnswerResult` gains `sessionId: string` and
  `turn: number` (kept identical across the mirror).

**Checkpoint (browser + script):** open a manual → URL carries `?s=<uuid>`; ask two
questions → reload → both turns rehydrate from `getSession`; a `chat_sessions` row exists
(`turn_count = 2`, `title` = the first question, `version_id` set, `summary = ''`); every
`query_log` row for the session shares that `session_id` with `turn` 1, 2; "New chat" gives
a fresh `?s=` + a new `chat_sessions` row + an empty thread; a student sees only their own
sessions (RLS); `run_evals.py --quick` **unchanged and green** (a single-turn call logs
`turn = 1`, creates a 1-turn `chat_sessions` row, and answers identically). `/code-review`.

### Phase 2 — conversational pipeline + history-aware verify (the eval-critical phase)

**Files**
- `supabase/functions/ask/pipeline.ts`:
  - **Assemble context.** `AskDeps.getHistory(sessionId)` returns
    `{ summary: string, summaryThroughTurn: number, recentTurns: { turn, question, answer,
    abstained, kind }[] }` — `summary` + `summary_through_turn` from `chat_sessions`; the
    recent turns are `query_log` rows for the session with `turn > summary_through_turn`,
    ordered by `turn`, then trimmed from the *oldest* end until they fit
    `HISTORY_RECENT_CHARS` (≈ 5000). `index.ts` wires it under the caller's JWT.
  - **Roll the summary.** If trimming dropped turns `[summary_through_turn+1 .. m]` (i.e. the
    recent window no longer starts right after the summary), one `chatJson` call folds those
    dropped turns *into the existing `summary`* (system: "extend this running summary of a
    Q&A conversation about a test manual with the new exchanges; keep it under
    `SUMMARY_MAX_CHARS` ≈ 1500; capture what was asked and the gist of each answer; **do not
    invent or restate specific numbers/scores as fact** — say e.g. 'discussed the PHQ-9
    severity bands' not the band values"). Persist `summary` + advance
    `summary_through_turn = m` on `chat_sessions`. This runs **only** when the window slides
    (never for short chats). The summary + recent turns then always cover the whole
    conversation with no gap.
  - **Condense:** if there is any history (summary or recent turns), one `chatJson` call →
    a standalone retrieval query (system: "using the running summary + recent turns, rewrite
    the user's latest question into a self-contained search query; do not answer; if already
    self-contained return unchanged; if it is about the conversation itself and not the
    manual, return the literal token `__META__`"). Embed + `match_chunks` use the standalone
    query. Retrieval is otherwise **unchanged** (one version, RLS, `RETRIEVE_K`).
  - **Meta path:** if condense returned `__META__`, answer from the transcript with a
    dedicated `chatJson` call (system: "answer only about this conversation; never state a
    fact about an instrument; no citations"), return `{ kind: 'meta', citations: [],
    abstained: false, answer }`, **skip verify**, log the turn.
  - **Answer:** `answerUserPrompt` gains `{ summary, recentTurns }`, clearly delimited as
    "Conversation so far — running summary + recent turns (context only — NOT a source of
    facts)". System prompt updated: cite only from the retrieved passages; the conversation
    and summary may be used to understand the question, never to support a claim.
  - **History-aware verify:** `verifyUserPrompt` still checks each claim against **this
    turn's retrieved chunks only** — neither the transcript nor the summary is passed to
    verify. Add an explicit instruction that a claim traceable only to "something said
    earlier" or "the summary" is *unsupported*. Unsupported claims are dropped exactly as
    today; empty → abstain.
  - `AnswerResult.kind: 'grounded' | 'abstained' | 'meta'` added to the schema + mirror;
    `abstained` stays a boolean derived from `kind === 'abstained'` for back-compat with
    `AnswerCard` / `toHistoryEntry`. `query_log` stores `kind` (new nullable column in the
    Phase 1 migration, or a Phase 2 follow-up migration — architect's call; nullable so old
    rows read as `'grounded' | 'abstained'` from `abstained`).
- `supabase/functions/_shared/prompt.ts` — the three system/user prompt edits above.
- `evals/` **(the gate)**:
  - `evals/conversational.py` **(new)** — a multi-turn runner: replays a scripted session
    (`sessionId` fixed) turn by turn against the deployed `/ask`, scoring the *final* turn.
  - `golden_dataset.jsonl` gains multi-turn cases in three categories, each a release blocker:
    - **follow-up-resolution** — turn 2 uses a pronoun / ellipsis that only resolves via
      turn 1; the answer must cite the correct chunk (RAGAS faithfulness unchanged).
    - **no-smuggle** — turn 1 answers about X; a later turn asks about Y that the manual does
      not contain; that turn **must abstain** — it must not reuse turn 1's fact. Include at
      least one *long* case (≥ 10 turns) so the fact has been folded into the rolling
      `summary` before Y is asked — the summary must not smuggle it either. Zero tolerance.
    - **meta** — "what did I just ask" / "what have we covered" → `kind: 'meta'`, correct
      recall, **no citation**, `abstained === false`.
  - `abstention.py` / `cross_version_leak.py` — unchanged; run as single-turn (history empty)
    and must stay 100% / zero-leak.
  - `run_evals.py` — add the conversational category to both `--quick` and full; keep LLM
    calls bounded (each multi-turn case is 2–3 `/ask` calls).
- `src/lib/schema.ts`, `src/components/AnswerCard.tsx` — render `kind: 'meta'` distinctly
  (a "from your conversation" label, no citation chips, not styled as an abstention).

**Checkpoint (script, against a deployed preview or the live function behind a flag):**
follow-up cases resolve and cite correctly; every no-smuggle case abstains (including the
long case where the fact is only in the rolling `summary`); meta cases return `kind: 'meta'`
with the right recall and no citation; a long session's `chat_sessions.summary` grows,
`summary_through_turn` advances, and the summary never contains a verbatim score/number;
**`abstention.py` still 100%, `cross_version_leak.py` still zero leaks, RAGAS ≥ the current
threshold**; latency per turn stays within the spec's 5–15 s band (the summary call fires
only when the window slides). `/code-review` — reviewer's explicit charge: can any input
(transcript, summary, an earlier turn's answer) make a grounded answer state a fact that
isn't in *this* turn's retrieved chunks?

## Verification step (whole addendum — hand to release-qa)

1. **Grounding guarantee (release blocker):** across the full multi-turn golden set, no
   grounded answer contains a claim absent from that turn's retrieved chunks — not via the
   transcript, not via the rolling `summary`, not via an earlier turn; `cross_version_leak.py`
   = zero leaks; `abstention.py` = 100% on the single-turn set; every **no-smuggle** case
   abstains (short *and* long / summary-folded).
2. **Conversational behaviour:** follow-up-resolution cases cite correctly; **meta** cases
   return `kind: 'meta'` with accurate recall, no citation, `abstained === false`.
3. **Sessions:** every `/ask` turn is logged with a stable `session_id` and a monotonic
   `turn`; a single-turn call is indistinguishable from v1.1.2 in `query_log`; RLS still
   self-or-admin; no update/delete path was added.
4. **Persistence & resume:** a reloaded Ask rehydrates from `getSession`; "Resume →" from
   "My answers" continues the same `session_id`; "New chat" starts a fresh one.
5. **No infra regression:** `/signin`, `/history` old links, ingestion, storage untouched;
   `pnpm lint` + `pnpm test` + `pnpm test:functions` + `pnpm build` green; full
   `run_evals.py` (not just `--quick`) green and at/above the current RAGAS threshold.
6. **Ship:** `supabase db push` (the session migration); `supabase functions deploy ask`;
   merge to `main` → CI → `deploy.yml` → Pages. `CLAUDE.md` updated (three response kinds,
   conversational-RAG description). No new Edge Function.

## Deviations from spec

*(app-developer appends during Build, release-qa during Verify. "None" if nothing diverged.)*

### Phase 1 (app-developer + self-review)

- **`chat_session_next_turn` is a `SECURITY DEFINER` RPC** (atomic `insert … on conflict do
  update … where user_id = auth.uid() returning turn_count`), not a "compute max(turn)+1 in
  the pipeline". Race-safe, and it raises `not your session` if the row belongs to someone
  else (verified live).
- **`evals/common.py` `call_ask` gained a `session_id` param** (fresh uuid per call by
  default) — the `/ask` body now requires `sessionId`. Single-turn eval behaviour unchanged;
  `run_evals --quick` stays 100% abstention.
- **`AnswerResult` gained `sessionId` + `turn`** (schema + mirror + the 2 fixture updates).
- **[low, fix in Phase 2 migration]** the RPC's `on conflict` clause checks `user_id` but not
  `version_id`, so a crafted client could log turns for two versions under one `session_id`
  (the SPA can't — Ask is locked to one route `versionId`). Add
  `and public.chat_sessions.version_id = p_version_id` to the `where`.
- **[low, fixed]** `Ask.tsx` rehydration now no-ops if a turn was already submitted while
  `getSession` was in flight (`setTurns(prev => prev.length ? prev : …)`).
- The Phase-1 checkpoint script's "pre-v1.2 row" date filter was wrong (matched same-day
  rows); backfill verified directly instead — 474/474 `query_log` rows tagged,
  `session_id === id`, `turn === 1`, 0 orphan sessions, 474 `chat_sessions` rows.

### Phase 2 (app-developer + self-review)

- **A first turn / single-turn call is byte-identical to v1.1.2.** `getHistory` returns no
  prior turns → `hasHistory` false → no condense, no summary, empty `conv` → `answerUserPrompt`
  emits the same prompt. This is why the existing abstention (100%) and cross-version-leak
  (zero) evals stay green unchanged.
- **verify never sees the transcript or the summary** — `verifyUserPrompt` gets only this
  turn's cited chunks (+2). The no-smuggle eval cases (incl. the 10-turn summary-fold)
  confirm a transcript-only claim is dropped → abstain.
- **Meta path** skips retrieval AND verify (`kind: 'meta'`, no citation). `condense` returns
  the literal `__META__`; a fixed fallback message is used if the meta LLM call fails.
- **`chat_session_next_turn` now also checks `version_id`** on conflict (the Phase-1 low
  item) — migration `20260911110000`.
- **[deviation — latency] a conversational turn now makes 3–4 LLM calls** (condense + answer
  + verify, plus a summary call when the window slides) vs 2 before, so a mid-conversation
  turn on the free model runs longer than the spec's 5–15 s band. Accepted: the user chose
  full-history ChatGPT-style memory over the condense-only option; a first turn is unchanged.
- **[low] the new condense / summary / meta prompts are not hardened against prompt-injection
  in a crafted question.** Blast radius is small — a poisoned condense output is just a
  search string fed to the version-filtered `match_chunks` (worst case: a poor retrieval →
  abstain); a poisoned summary only feeds question-understanding and never a claim (verify
  still gates). Worth an adversarial eval case later.
- **Checkpoint (conversational eval, live):** 6/6 — `followup-*` grounded + cited
  (ellipsis "and for 18-29?" → cites 14.2, confirmed in-browser 13.7→14.2);
  `meta-*` `kind: 'meta'` + no citation (in-browser: "From your conversation" card,
  recalls the first question); `nosmuggle-phq-then-other-instrument` + the 10-turn
  `nosmuggle-long-summary-fold` both abstain. Single-turn abstention 100%,
  cross-version 4/4 zero leaks.

### Phase 3 (app-developer + self-review)

- **`/history` restructured from a flat per-answer list into a conversation-card list.**
  `listMyHistory` → `listMySessions({ versionId?, before?, limit })` (keyset on
  `(last_at, id)` over `chat_sessions`, RLS self); a card expands to lazily-fetched
  `getSession(sessionId)` turns (each rendered by the shared `AnswerCard`, no `/ask` call).
- **`AnswerCard` gained a `meta` branch** — `result.kind === 'meta'` renders a "From your
  conversation" card (no citation chrome, no slide-over).
- **Resume is a link, not a copy.** `Resume this conversation →` navigates to
  `/ask/:versionId?s=:sessionId`; `Ask.tsx` reads `?s=`, and on a fresh load with no `?s=`
  it mints one (`newSessionId()` → `crypto.randomUUID()`) and `replace`s it into the URL, so
  every conversation has a stable id from the first turn and a reload keeps the thread.
- **Resume hidden for an archived/removed manual** (`s.manualActive`), matching the v1.1
  "Re-ask" gate.
- **`kind` is backfilled at read time** — `toHistoryEntry` derives `kind` from the stored
  `kind` column, falling back to `abstained ? 'abstained' : 'grounded'` for pre-v1.2 rows
  that predate the column.
